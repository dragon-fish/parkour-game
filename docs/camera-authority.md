# 镜头权属：谁在动身体，决定镜头要不要跟手

← 返回 [README](../README.md)

一条在这个项目里反复出现、每次都以同样方式被违反的原则。

## 原则

**镜头不必与胶囊逐帧同步。** 该不该同步，取决于**是谁在动身体**：

| 位姿变化来自 | 镜头 | 理由 |
|---|---|---|
| **玩家输入**（鼠标、WASD） | **必须跟手**，零延迟 | 输入延迟无法忍受，玩家会立刻察觉 |
| **物理**（重力、碰撞、坠落） | 跟手 | 那是世界在回应玩家，看得见才有反馈 |
| **脚本**（step-up、对齐、演出） | **应当滞后并平滑追上** | 那是发生在玩家身上的事，硬切等于跳剪 |

第三行是被反复违反的那一行。

## 已经踩过的三次

**楼梯（step-up）。** `try_step_up()` 把身体瞬间抬高，中间地面吸附又把它拽回，一级台阶
其实是一串上下抖动。最初的做法是"每次抬升时推一个相机偏移再衰减"——它只听得见"抬"、
听不见"拽回"，于是一路和物理对着干，玩起来是镜头一路抖上楼梯。
**最终解法**：镜头以固定速率**追身体的高度**，身体怎么抖都无所谓
（`CameraRig._eye_ground_y`）。

**死亡演出。** 相机被过场接管，位姿逐帧由 `DeathSequence` 指定，`update_effects()`
整个让位（`CameraRig._cinematic`）。这一档是完全接管，不是滞后。

**抓边对齐（IntoGrab）。** 够取动作把身体转正对墙，有时要转几十度。直接转，镜头就被
一刀切过去。**解法**：动作**显式告诉**相机自己转了多少
（`CameraRig.absorb_body_yaw()`），相机把这一笔记成滞后量再平滑抹平。

## 为什么是"显式告诉"而不是自动检测

镜头无法自己分辨"身体转了 30 度"是玩家甩鼠标还是脚本对齐，而这两者要求相反的处理。
试图从上一帧的差值反推来源，就是在猜。让动作自己报账，来源是确定的，代价是一行调用。

同理，高度那一档之所以能自动（`_eye_ground_y` 直接追身体高度），是因为**所有**改变身体
高度的东西都该被平滑——台阶、吸附、接缝——没有"必须跟手的高度变化"这种东西。
唯一的例外是坠落，而它由 `grounded` 显式排除。

## 落地检查清单

新增一个会**由脚本移动或旋转身体**的动作时：

- 位移是**高度**：什么都不用做，`_eye_ground_y` 已经覆盖。
- 旋转是**偏航**：调 `camera_rig.absorb_body_yaw(实际转过的角度)`。
- 要**完全接管**镜头（过场）：`begin_cinematic()` / `set_cinematic_pose()` / `end_cinematic()`。
- 施加的是**额外角度**而非位姿（落地下沉、翻滚翻转）：各走各的通道
  （`set_landing_pitch_offset()` / `set_roll_spin()`），不要挤进同一个字段——
  翻滚要越过垂直线，而落地下沉恰恰不许越过，两者塞在一起会互相钳制。
