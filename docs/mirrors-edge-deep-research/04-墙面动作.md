# 04 · 墙面动作

← [README](README.md) · 上一篇 [03-损速机制](03-损速机制.md)

墙面系统是镜之边缘辨识度最高的部分，也是参数最密集的部分。**这一章有本手册最重要的单条发现**（见 4.4）。

一个前置澄清：游戏里有**四个独立的墙面 Move 类**，社区术语经常把它们混为一谈：

| 类 | 触发情境 | 通俗叫法 |
|---|---|---|
| `TdMove_WallRun` | 侧向贴墙横跑 | wallrun |
| `TdMove_WallClimb` | 正面朝墙向上跑 | wallclimb / vertical run |
| `TdMove_WallKick` | 空中朝墙踢蹬 | wallkick |
| `TdMove_WallrunJump` | **从 wallrun 状态跳离** | wall boost ← 关键 |

---

## 4.1 Wallrun（贴墙横跑）

✅ **确证** — `TdMove_WallRun` CDO：

### 进入条件

| 参数 | 值 | 含义 |
|---|---|---|
| `WallRunningMinSpeed` | 200 uu/s | 低于 2 m/s 无法起跑 |
| `WallRunningVelocityStartLimit` | 300 | 起跑速度判定阈值 |
| `WallRunningMinWallHeight` | 192 uu (1.92 m) | 墙必须够高 |
| `WallRunningForwardMinStartAngle` | 0° | 正面入射角下限 |
| `WallRunningForwardMaxStartAngle` | **57°** | 正面入射角**上限** |
| `WallRunningStrafeStartAngle` | **60°** | 侧向入射角阈值 |
| `WallRunningForwardCheckDistance` | 50 uu | 前向检测距离 |
| `WallRunningStrafeCheckDistance` | 50 uu | 侧向检测距离 |
| `WallRunningDistanceForIntoWall` | 180 uu | 触发"扑向墙"的距离 |

**入射角是硬判定**：0–57° 走 forward 分支，60° 以上走 strafe 分支。57°–60° 之间这 3 度的缝隙很可能是有意的迟滞带（hysteresis），防止在临界角来回抖动。

### 持续与衰减

| 参数 | 值 | 含义 |
|---|---|---|
| `WallRunningHorisontalFriction` | **0.05** | 贴墙期间摩擦力只有 5% |
| `WallRunningHorisontalAcceleration` | 820 uu/s² | 沿墙加速度 |
| `WallRunningHorisontalDeceleration` | 500 uu/s² | 沿墙减速度 |
| `WallRunningVelocityStopLimit` | −500 | 掉速到此值退出 |
| `WallRunningHorisontalInitialZHeight` | 170 uu | 进入时的初始抬升高度 |
| `WallRunningHorisontalAlignSpeed` | 700 | 对齐墙面的速度 |
| `WallRunningRotatePawnAlongWallTime` | 0.4 s | 身体转向贴合墙面的时长 |
| `MinimumVelocityIntoWall` / `Maximum` | 600 / 700 | 撞墙速度区间（触发镜头效果） |
| `RedoMoveTime` | 0.15 s | 冷却 |
| `TimeToDo90Turn` | 0.25 s | |

**没有"最长持续时间"参数**。⚠️ 推断：wallrun 不是靠计时器结束的，而是靠 `WallRunningVelocityStopLimit = -500` 的**速度衰减**自然结束——摩擦力 0.05 极低（几乎不掉速），但减速度 500 持续作用，速度掉到阈值就退出。**这是一个纯粹由动量决定时长的设计**：跑得越快，贴得越久。

### 镜头约束

✅ `MinLookConstraint = (-13000, -16384, -32768)`、`MaxLookConstraint = (13000, 16384, 32768)`

UE3 角度单位 65536 = 360°，换算：

- **Pitch（俯仰）限制 ±13000 = ±71.4°**
- **Yaw（左右）限制 ±16384 = ±90°**

贴墙期间玩家的视角被**硬性锁在 ±90° 的扇形内**，不能回头。配合 `bConstrainLook = True`、`bUseAbsoluteYawConstraint = True`。这是"贴墙时镜头自动看向前进方向"体感的来源——不是动画，是输入约束。

## 4.2 Wallclimb（垂直爬墙）

✅ **确证** — `TdMove_WallClimb` CDO：

| 参数 | 值 | 含义 |
|---|---|---|
| `WallClimbingVerticalStartAngle` | **33°** | 入射角阈值（源码里注释掉了旧值 `//55`） |
| `WallClimbingMaxDistance2D` | 120 uu | 水平检测距离 |
| `WallClimbingVelocityStartLimit` | 0 | **无最低速度要求** |
| `WallClimbingVerticalFriction` | 6.0 | 垂直摩擦（很高，快速衰减） |
| `WallClimbingGravity` | **800** | 与世界重力相同 |
| `AddOnSpeed2DHeight` / `MaxLimit` | 60 / 650 | 水平附加速度的高度与上限 |
| `AddOnSpeedZHeight` / `MaxLimit` | 130 / 320 | 垂直附加速度的高度与上限 |
| `MinWallHeight` | 180 uu | |
| `MinLegdeZNormal` | 0.707 | 可抓边缘的法线下限（= 45°），注意原文拼写错误 `Legde` |
| `FrictionModifier` | 0.3 | |
| `MinUpwardsVelocityToDoubleJump` | 100 | |
| `MaxIntoWallClimbVelocityToDoubleJump` | 100 | |

**关键对比**：wallclimb 的入射角阈值是 **33°**（要相当正对墙面），wallrun 是 **57°/60°**。这就是"对着墙跑就往上爬，斜着跑就横着跑"的判定分界。⚠️ 注释掉的 `//55` 说明 DICE 中途把这个阈值从 55° 收紧到 33°——大概是因为 55° 时玩家想 wallrun 却总是触发 wallclimb。**这条注释是难得的设计迭代痕迹。**

🔶 **推导爬升高度**：`AddOnSpeedZMaxLimit = 320` uu/s，在重力 800 下能再爬升 320²/(2×800) = 64 uu；加上 `AddOnSpeedZHeight = 130`，总有效爬升在 **190–200 uu（约 2 m）** 量级，与 `MinWallHeight = 180` 自洽。

## 4.3 Wallkick（空中踢墙）

✅ **确证** — `TdMove_WallKick` CDO：

| 参数 | 值 | 公制 |
|---|---|---|
| `WallKickVelocity2D` | 300 uu/s | 3.0 m/s 水平 |
| `WallKickVelocityZ` | **580 uu/s** | 5.8 m/s 垂直 |
| `WallKickMaxDistance` | 60 uu | 离墙最大触发距离 |
| `WallKickCheckHeight` | 90 uu | 检测高度 |
| `WallKickExtentWidth` / `Height` | 20 / 10 | 检测盒尺寸 |
| `RedoMoveTime` | **1.0 s** | **同一动作 1 秒冷却** |
| `PawnPhysics` | `PHYS_Falling` | |

🔶 **推导轨迹**（假设 2D 分量是覆盖而非叠加）：垂直 580 → 滞空 2×580/800 = **1.45 s**，水平飞行 300 × 1.45 = **435 uu = 4.35 m**。

垂直分量 580 接近普通跳跃的 630——**踢墙几乎等于一次完整的额外跳跃**。这就是它作为爬升手段的价值。

⚠️ `RedoMoveTime = 1.0` 是本手册里最长的冷却之一，明确回答了你的问题：**不能对同一面墙连续快速踢**。1 秒的冷却意味着必须找到另一面墙，或者接受高度损失。

⚠️ 未确证：`WallKickVelocity2D = 300` 是**设置**水平速度还是**叠加**到现有速度。若是覆盖，踢墙就是净损速（因为跑速可达 720）；若是叠加，则是加速手段。📣 社区把 wallkick 主要当作**爬升/续航**手段而非提速手段，这倾向于"覆盖"或"设为最小值"。

## 4.4 ⭐ WallrunJump：DICE 把技巧梯度写进了参数名

这是本手册最重要的单条发现。

✅ **确证** — `TdMove_WallrunJump` CDO：

```
WallRunningPushAwaySpeedNoob         = 120      ← 字面意思：菜鸟
WallRunningPushAwaySpeedProAdd       = 400      ← 字面意思：高手加成
WallRunningPushForwardSpeedMin       = 0.1
WallRunningJumpOffZHeightForward     = 100
WallRunningJumpOffZHeightMaxAddTurned = 60
```

**DICE 直接在参数名里写了 `Noob` 和 `ProAdd`。** 从 wallrun 跳离墙面时获得的推离速度不是常数，而是一个区间：

```
最差执行:  120 uu/s
最好执行:  120 + 400 = 520 uu/s        ← 4.3 倍差距
```

同理垂直分量：基础 `100`，转身角度对时可再加 `60`（最高 160）。

⚠️ 中间值由什么插值，参数名没说，但结合 📣 社区实测几乎可以确定是**离墙瞬间的视角朝向与墙面的夹角**：

> 「贴墙跑时**尽量正面朝向所贴的墙**（但不要直接撞上去）再跳，会获得显著速度增益。」
> 「wallrun 时看向所贴的墙并起跳，速度可超过 20 mph（≈894 uu/s），高于常规跑速 16 mph 与跳跃 18 mph。」

社区管这个叫 **wall boost**，多年来只知其然（有帖子直言"for whatever reason gain speed"）。**逆向数据给出了答案：那不是 bug，是 DICE 显式设计的 120→520 技巧梯度。**

### 🎯 这条交叉验证的分量

| 社区观察 | 逆向数据 | 结论 |
|---|---|---|
| "wall boost 能超过常规速度上限" | 推离速度最高 520，且 `AirSpeed = 2400` 不限速 | ✅ 机制成立 |
| "增益大小取决于你朝向墙的角度" | `Noob` 120 → `ProAdd` +400 的连续梯度 | ✅ 确认 |
| "原因不明" | 参数名直接写着 Noob/Pro | ✅ **解答** |
| speedrun.com 把 wallboost 归为 glitchless 合法技术，还分出 Gap / Double / Pole 三种变体 | 是设计内机制，不是 bug | ✅ 社区判断正确 |

📣 另有社区结论：**wallrun 结束落地瞬间动量会大幅提升，常常直接拉满到最高冲刺速度**，某 wiki 称其为"游戏中最快的通用移动方式"。⚠️ 这与 4.4 的推离速度是否同一机制未确证。

### 对复刻的启示

**如果你的墙跳给固定冲量，你就丢掉了镜之边缘最核心的技巧梯度。** 这个 4.3 倍的区间是"新手能玩、高手有得练"的全部来源——它让同一个按键在不同执行质量下产生天差地别的结果，而且**不需要额外按键、不需要 QTE、不需要教学**。

## 4.5 墙面相关的其他跳跃

✅ **确证**：

| 类 | 参数 | 说明 |
|---|---|---|
| `TdMove_WallClimbDodgeJump` | `BaseJumpZ=700`、`JumpAddXY=150`、`DodgeJumpInertiaConservation=**1.0**` | 从爬墙状态侧跳，**100% 保留惯性** |
| `TdMove_WallrunDodgeJump` | `BaseJumpZ=300`、`JumpAddXY=600`、`InertiaConservation=**0.3**` | 从 wallrun 侧跳，只保留 30% 惯性，但水平推力 600 很大 |
| `TdMove_WallClimb180TurnJump` | `JumpOffZHeight=250`、`JumpPushAwaySpeed=400`、`JumpTimeWindow=**0.6**` | 爬墙后转身跳，**0.6 秒输入窗口** |
| `TdMove_DodgeJump` | `BaseJumpZ=300`、`JumpAddXY=600`、`InertiaConservation=0.3`、`StrafeThreshold=0.99` | 普通侧跳 |

**`DodgeJumpInertiaConservation` 是显式的惯性保留系数**——0.3 vs 1.0 的差别意味着"从哪个状态跳出去"决定了你能带走多少速度。这是一张需要玩家记忆的隐藏收益表，也是速通路线规划的基础。

⚠️ `TdMove_DodgeJump.StrafeThreshold = 0.99` 推断为：侧移输入必须几乎纯粹（点积 > 0.99）才触发侧跳。📣 社区的 **side-jump boost / sidestep boost**（侧走起跳后空中转身即达最高速）正是利用这个动作——`JumpAddXY = 600` 的水平推力配合空中转向，绕过了 [02](02-速度系统.md) 那条 7 秒的加速曲线。社区称其为一代绕过加速曲线的主要手段，且属 glitchless 合法。
