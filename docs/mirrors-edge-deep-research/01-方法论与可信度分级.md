## 数据来源

本手册的数值来自三条独立管线，互相交叉验证。

### 来源 A：游戏原始配置文件（明文）

Steam 正版《Mirror's Edge》(2008) 安装目录：

```
<Steam>\steamapps\common\mirrors edge\TdGame\Config\
    DefaultPawnMovement.ini    ← 全部移动动作的调参
    DefaultGame.ini            ← Pawn 基础属性、重力
    DefaultAnimation.ini / DefaultCamera.ini / DefaultInput.ini
```

游戏内部代号是 **Takedown**，所以类前缀全是 `Td`。这些 `.ini` 是明文，直接可读，是可信度最高的一手数据。

### 来源 B：编译后 UnrealScript 包的反序列化（自研工具）

`TdGame\CookedPC\TdGame.u`（29 MB）包含全部游戏逻辑。它是 **LZO 压缩**的 UE3 包（FileVersion 536 / LicenseeVersion 43），需要先解压再解析：

1. `tools/ue3_decompress.py` — 解析包头的 compressed-chunk 表，逐块 LZO 解压 → 58.9 MB 平坦文件
2. `tools/ue3parse.py` — 解析 name table / import table / export table（20592 names、2246 imports、52410 exports、916 classes）
3. `tools/dump_cdo.py` — 解析每个 `Default__<Class>` 对象的 tagged property 列表，得到类默认属性
4. `tools/dump_struct.py` — 递归解析嵌套 struct 与 array（速度曲线就藏在这里）

`TdGame.u` 与 `Engine.u` 合计 **2031 个 CDO 全部解析成功，0 失败**。

> **踩过的坑**（复现时注意）：
> - export 表在 FileVersion < 543 时含 `ComponentMap` 字段，漏掉会导致偏移全错
> - 本版本的 `ByteProperty` tag **不含** enum 名字段，8 字节直接是值的 FName
> - `BoolProperty` 的值是 **4 字节 int**，不是 1 字节

**这不是破解**：读取的是自己合法购买的游戏的数据文件，不涉及绕过 DRM，也不分发游戏资源。仓库里只有提取出的数值和自研脚本。

## 可信度分级

全手册统一使用以下标记：

| 标记 | 含义 |
|---|---|
| ✅ **确证** | 直接从 `.ini` 或 CDO 二进制读出的原始数值，无解释成分 |
| 🔶 **推导** | 由确证数值经物理公式计算得出（如跳跃高度 = v²/2g），计算过程已给出 |
| ⚠️ **推断** | 参数名含义或语义由命名和上下文推测，**未经字节码验证** |
| 📣 **社区** | 来自速通社区实测或共识，非一手数据 |
| ❓ **未知** | 找不到、或来源互相矛盾 |

### 本研究的已知边界

**没有做字节码反编译。** `TdGame.u` 里的 UnrealScript 函数体（即真正的**公式**）没有解出来——只解了数据，没解代码。因此：

- 所有**参数值**是确证的；
- 所有**参数如何被使用**（乘上去？减掉？作为上限？）在没有社区实测佐证时只能标 ⚠️。

典型例子：`LandingSpeedReduction = 65` 这个值 100% 确证，但它是"损失 65%"还是"保留 65%"还是"减去 65 uu/s"，二进制数据本身回答不了。这类问题正是交叉验证要解决的，见 [03-损速机制](03-损速机制.md)。

如果后续要补齐公式，路径是用 **UE Explorer**（EliotVU 的 UE3 反编译器）打开 `TdGame.u`，它能输出可读的 UnrealScript。本研究没走这条路是因为它是 GUI 工具。
