# 15 · 原版逻辑反编译

本章记录从原版二进制直接读出来的**逻辑**：公式、判定顺序、常数。
它补的是 [01 §已知边界](01-方法论与可信度分级.md) 写下的那条"硬边界"：
"不做字节码反编译"、"原生 C++ 拿不到"。这两条现在都不成立了。

本章只写推导后的公式和行为描述。反编译的原始输出可以随时用 [tools/](tools/README-reverse-engineering.md)
重新生成，不入库。

## 15.1 结构：两层，分工明确

- **脚本层**（`TdGame.u`，UnrealScript）：每个 move 的 `CanDoMove` / `StartMove` / `StopMove` /
  `HandleMoveAction`，按键动作仲裁（`TdPlayerMoveManager.HandleMoveAction`），控制器状态里的
  `PlayerMove`。142 个 `TdMove_*` 类共有 913 个脚本函数，原生函数只有 38 个。
- **原生层**（`MirrorsEdge.exe`，C++）：加速度计算、物理（walking / falling / 墙跑 / 蹬墙）、
  环境探测（`FindLedge`、`FindWallSide` 等）、**自动转移开关**（`bCheckForGrab`、
  `bCheckForVaultOver`、`bCheckForWallClimb`、`bCheckForEdgeInVelDir`、`bCheckExitToFalling`）。
  这些开关在脚本里只声明、只赋值，没有任何读取。

原生代码按偏移访问字段。偏移由 [tools/ue3_layout.py](tools/ue3_layout.py) 从反编译出的声明顺序算出，
已用 `Actor.Physics = 0x68`、`Actor.Velocity = 0x100`、`sizeof(ATdPawn) = 0x8f8`（来自 exe 的类注册）校验。

## 15.2 地面与空中加速度 `[ME:CONFIRMED emulated]`

`TdPlayerController.PlayerWalking.PlayerMove` 每帧决定调用哪一个：

```
WalkDirection = Normal(aForward * X + aStrafe * Y)          // X, Y = Pawn 朝向的轴
if Physics == PHYS_Falling:
    Accel = GetSprintAcceleration(aForward, aStrafe, aTurn, dt)
elif |WalkDirection.xy| > 0:
    AccelerationTime += dt;  StoppingVelocity = 200
    Sprint = aForward > 0.7 && InputSize > 0.7 && Velocity · WalkDirection > 0
    if Sprint:                 Accel = GetSprintAcceleration(...)
    elif |WalkDirection| > 0.5: Accel = GetWalkAcceleration(...)
    else:                      aForward = 0.1·sign(aForward); aStrafe = 0.1·sign(aStrafe)
                               Accel = GetWalkAcceleration(...)
else:
    Accel = GetWalkAcceleration(...)
    if 0 < AccelerationTime < 0.15:                 // 点按急停
        bIsStopping = true; SetTimer(0.25, 'PlayStop')
        StoppingVelocity = 35; Velocity = Normal(Velocity) * 35
    AccelerationTime = 0
// bIsStopping 期间（MovementState == Walking）：Velocity = Accel = Normal(Velocity) * StoppingVelocity
```

阈值 `InputMaxSprintHeightLimit = InputMaxSprintRaduisLimit = 0.7`。

### 加速度曲线（运行时生成）

`AccelCurve_LightWeapon` / `AccelCurve_HeavyWeapon` 是 `transient` 的，CDO 里没有值，
由原生代码在初始化时从 `SpeedCurve_*`（时间 → 速度）生成"速度 → 加速度"：

1. 在 SpeedCurve 上等距取 `点数 × 10` 个时刻 t，建一条"速度 → 时间"的线性反查曲线。
2. 对 `i = 0..10`：`s = i · Vmax / 10`，反查得 t，加速度 = `(Speed(t + 0.05) − Speed(t)) / 0.05`。
3. 11 个点，线性插值，超出两端取端点值。

用 CDO 的 `SpeedCurve_LightWeapon`（(0,0) (0.4,400) (1,520) (3.5,650) (7,720)）生成的结果：

| 速度 uu/s | 0–288 | 360 | 432 | 504 | 576 | 648 | 720 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 加速度 uu/s² | 1000 | 674.8 | 200 | 200 | 52 | 44.6 | 0 |

### `GetSprintAcceleration(aForward, aStrafe, DeltaRotation, dt)`

```
speed = |Velocity.xy|
dir = SafeNormal(X·aForward + Y·aStrafe);  若 dir 三个分量都 < 1e-4：SpeedSprintEnergy = 0，返回 0
SpeedSprintEnergy = max(speed − SpeedMaxBaseVelocity, 0)
A = dir · AccelCurve_LightWeapon.Eval(speed)
if 手持重武器（MyWeapon.WeaponType == 1）:
    top = AccelCurve_HeavyWeapon 最后一个点的 InVal
    A = speed ≤ top ? dir · AccelCurve_HeavyWeapon.Eval(speed) : −dir · (speed − top)
if Physics != PHYS_Falling:
    d = dir.xy · speed − Velocity.xy                     // 把速度掰向输入方向
    k = min(SpeedSprintVelocityAccelerationFactor · |d|, |d| / dt)
    A += Normal(d) · k + Velocity · GroundFriction · 0.1
A −= Velocity · SpeedTurnDecelerationFactor · |DeltaRotation| / 32768     // 转向惩罚，空中也生效
return round(A, 0.1)                                                    // floor(10A + 0.5) / 10
```

- `DeltaRotation` 是 `int(PlayerInput.aTurn)`，即**本帧的鼠标偏航输入量**（旋转单位）。
  转向惩罚的形式是：速度矢量的一个比例，**与本帧的转动量成正比**，不与转过的总角度成正比。
- `+ Velocity · GroundFriction · 0.1` 用来抵消随后物理里的地面摩擦。`GroundFriction` 取自所在 `PhysicsVolume`（UE3 默认 8）。
- 空中（`PHYS_Falling`）没有"掰向"项，也没有摩擦补偿，只有曲线加速度和转向惩罚。

### `GetWalkAcceleration(aForward, aStrafe, DeltaRotation, dt)`

```
dir = SafeNormal(X·aForward + Y·aStrafe);  若 dir 三个分量都 < 1e-4：SpeedSprintEnergy = 0，返回 0
if SpeedSprintEnergy > 0:                                  // 能量随时间衰减
    f = clamp(dir · X, 0, 0.9) ^ SpeedEnergyDecelerationExponent
    SpeedSprintEnergy −= (GroundSpeed − SpeedMaxBaseVelocity) · (1 − f) / SpeedEnergyDecelerationTime · dt
    SpeedSprintEnergy = max(SpeedSprintEnergy, 0)
top = SpeedMaxBaseVelocity − SpeedMinBaseVelocity + SpeedSprintEnergy
wantX = (dir·X) · SpeedMinBaseVelocity + top · aForward
wantY = (dir·Y) · SpeedMinBaseVelocity + top · aStrafe
A = X · (wantX − Velocity·X) · SpeedWalkVelocityAccelerationFactor
  + Y · (wantY − Velocity·Y) · SpeedStrafeVelocityAccelerationFactor
if Physics != PHYS_Falling: A += Velocity · GroundFriction · 0.1
return round(A, 0.1)
```

- `DeltaRotation` **不参与**行走加速度：行走时没有转向惩罚。
- 底数上限 **0.9** 意味着即使正对前方走，能量也会以 `(720 − 400)/3 · (1 − √0.9) ≈ 5.5 uu/s` 每秒的速率衰减；
  侧向、后退输入时 `f → 0`，衰减为满速 `106.7 uu/s` 每秒。
- 冲刺分支每帧直接把 `SpeedSprintEnergy` 设成 `speed − 400`；行走分支让它衰减；行走的目标速度是 `390 + 能量`。

CDO：`SpeedMaxBaseVelocity 400`、`SpeedMinBaseVelocity 10`、`SpeedWalkVelocityAccelerationFactor 7`、
`SpeedStrafeVelocityAccelerationFactor 10`、`SpeedSprintVelocityAccelerationFactor 30`、
`SpeedEnergyDecelerationTime 3`、`SpeedEnergyDecelerationExponent 0.5`、`SpeedTurnDecelerationFactor 10`、
`GroundSpeed 720`、`AccelRate 6144`、`AirControl 0.025`。

## 15.4 强制一帧 Walking 与"上一个状态" `[ME:CONFIRMED decompile]`

很多动作在动画结束、到达目标或落地时直接 `SetMove(Walking)`：180Turn、AutoStepUp、StepUp、Barge、AirBarge、
Climb、Landing、LayOnGround、LedgeWalk、全部近战、SkillRoll、SpringBoard、Stumble、Vertigo、Interact 等。
这一帧会产生两个影响：

1. 执行 `Walking.StartMove`：其中会清零 `bIllegalLedgeTimer`（`WallRunJump` 把它设成 2 s，并记下墙的法线）。
2. 改写 `OldMovementState`。大量 `StartMove` 按它分支，例如：
   - `WallRun.StartMove`：只有上一个状态是 WallRunJump 时，`ConsequtiveWallruns` 才加 1；
   - `Landing.SubtractLandingSpeed`：只在上一个状态是起跳类时才压速度；
   - `Falling.StartMove`：前驱为 Walking 且身体在倒退时，水平速度清零（倒着走下台阶）。

## 15.5 墙面动作 `[ME:CONFIRMED decompile]`

**WallRun.StartMove**：`WallRunningBeginSpeed = |Velocity.xy|`；若正在上升，取 `max(…, 300)`。
上一个状态是 WallRunJump 时 `ConsequtiveWallruns += 1`，滑墙的加速度与减速度都乘以 `(1 + n)`，否则 n 归零。
初始竖直速度 `sqrt(2 · h · WallRunningHorisontalAcceleration)`，其中
`h = min(170, 头顶净空) − (当前高度 − 起跳高度)`，下限为 0；只在上升中、且上一个状态不是 WallRunJump 时才设置。
视角偏航约束为 `[墙法线, 墙法线 + 90°]`（右墙）或 `[墙法线 − 90°, 墙法线]`（左墙）。
`ReachedWall`：水平速度保持方向，大小设为 `WallRunningBeginSpeed`。
`HandleMoveAction(Turn)`：镜头 0.15 s 转到墙法线，`bTurned90FromWall = true`。

**视角约束**（`TdMove.ConstrainAxis`）：超出范围时，每帧把偏移量拉回 `超出量 × dt / 0.2`，
朝外的输入照常生效，朝内的输入被吃掉；接近边界（超过 60%）时输入被衰减。

**WallRunJump.StartMove**：

```
p = 墙法线2D · 镜头朝向2D           // bTurned90FromWall 时镜头取墙法线，p = 1
FMax(0, p)                          // 结果被丢弃：p 不被钳制
h = 100 + 60·p；若头顶被挡，h = 到挡板的距离
Vz = g · 2 · sqrt(h / g) / (1 + ConsequtiveWallruns)
Vxy = 墙法线 · (120 + 400·p) + 沿墙速度 · (0.1 + 0.9·(1 − p))
```

另外设 `bIllegalLedgeTimer = 2`、`IllegalLedgeNormal = 墙法线`；视角约束为
`[法线 − 16000, 法线 + 10000]`（左墙跳出时相反）。

**WallRunDodgeJump**（墙跑中朝离墙方向横移再按跳）：`Velocity = ±600 · 右方向 + 0.3 · Velocity`，`Vz = 300`。

**WallClimb180TurnJump**：转身动画；0.6 s 窗口内按跳：`Velocity = 墙法线2D · 400`，跳高 250。

**WallClimbDodgeJump**：`State == WallClimbing && (Hint == 左 || Hint == 右)` 时可用；
`Velocity = ±150 · 右方向 + 1.0 · Velocity`，`Vz = 700`。0.5 s 内关闭抓边、翻越和蹬墙检测。

**MeleeWallrun**（墙跑踢，无目标）：速度绕竖直轴旋转 ±6000（32.96°）离开墙面，再 ×1.2；
动画结束后强制 Walking。有目标时速度改为朝向目标，大小为 `0.75 · |Velocity.xy|`。

**WallKick**：`CanDoMove()` 恒为 false，发售版里不可达。

## 15.6 落地与飞踢 `[ME:CONFIRMED decompile]`

**Landing.SubtractLandingSpeed**：条件为 `(上一个状态 == Falling && Falling 的前驱 ∈ {Jump, MeleeAir}) || 上一个状态 ∈ {Coil, MeleeAir}`，
并且武器类型不是 1。若 `PreJumpMomentum − 65 < |Velocity.xy|`，水平速度压到 `PreJumpMomentum − 65`。
`PreJumpMomentum` 只由 `TdMove_Jump` 写入，跨动作残留。

**MeleeAir**：可以从 IntoGrab / Jump / Falling / WallRunJump / GrabJump 发起（起跳 0.1 s 内不行），
水平速度超过 200 uu/s 时（MAT_FromJump）飞踢本身不改速度，没有目标时镜头 0.2 s 下压到 `Pitch −6000`；
更慢时（MAT_FromJumpStill）竖直速度当场清零。MAT_FromJump 落地时先调 `TdMove.Landed`——也就是照常进 Landing、
照常 SubtractLandingSpeed——再 `SetMove(Walking)`（Landing 通常已经设过）；只有已经踢中东西才不经 Landing。
MAT_FromJumpStill 落地什么都不做，等动画结束进 Falling 再落一次地。

**TdFallHeightVolume.Touch**：任何 TdPawn 一碰到就 `EnterFallingHeight = Center.Z + FallHeightOffset`，
再调当前 move 的 `TouchedFallHeightVolume()`，没有别的条件。`Center` 是 TdMovementVolume 烘焙进地图的字段，
即笔刷在世界里的中心（PrePivot 已算进去）；`FallHeightOffset` 没有类默认值，未设即 0。
只有 RumpSlide 覆盖 `TouchedFallHeightVolume`（置 `bTouchedFallHeightVolume`，StartMove 清零），
Landing 的硬着陆分支是 `bHardLanding && (!bUncontrolledSlide || (OldMovementState == RumpSlide && bTouchedFallHeightVolume))`。
关卡里的偏移从 −10 m 到 +1000 m 以上，有几个由 Kismet 的 `SeqAct_ChangeCollision` 开关（初始无碰撞）。

## 15.7 空中物理 `[ME:CONFIRMED emulated]`

玩家跑的是 `ATdPlayerPawn::physFalling`（TdPawn 本身不重写，TdPlayerPawn 重写）。

**重力 2 倍的真正来源是积分方式，不是常数。** `GetGravityZ = DefaultGravityZ(−800) × GravityModifier`，
全链路没有任何倍率。每个子步：`V1 = V0 + a·dt`，按 `V1·dt` 移动，然后**重建速度**
`Velocity = 2·(位移 / dt) − V0 = V0 + 2a·dt`。展开后 `V(T) = V0 + 2aT`、`X(T) = V0·T + aT²`，
与步长无关，是一条加速度为 2a 的抛物线。语料 02 §2.4 测到的 1600 是对的，"隐藏倍率"的解释作废；
而且**翻倍对整个加速度矢量都成立**，包括水平方向的空中操控。脚本里的 `GetGravityZ()` 返回 −800，
只有实际感受到的一半，`TdMove_Jump` 的抓边预测用的就是它。

**空中加速度上限**（脚本传进来的是 `GetSprintAcceleration` 的结果，Z 置零）：

| 水平速度 | 上限 uu/s² | 翻倍后 |
| --- | --- | --- |
| < 10 | 153.6 + (10 − v)/dt | — |
| 10 – 720 | `AccelRate × AirControl` = 6144 × 0.025 = 153.6 | 307.2 |
| ≥ 720 | **1.0** | 2.0 |

冲刺起跳约 820 uu/s（720 + 起跳前向 100），所以几乎没有空中转向，也几乎没有空中转向惩罚；空中没有阻力。
终端速度 3500 限制整个速度矢量的长度，在重建之后施加。

**子步**：一帧超过 0.05 s 时切成 `min(0.05, 剩余/2)`，连同调用方已用掉的次数最多 8 次，多余的时间丢弃；
60 fps 下每帧恰好一步。

**撞墙**：`processHitWall` → 当前 move 的 `HitWall`；然后 `ComputeSlideVector`
（`Delta = (Adjusted − N(Adjusted·N))(1 − t) − Normal(proj)·push`，接近竖直的墙额外推开 1%），
被挡住的那部分时间直接丢掉，不退还。

**落地**：速度取本子步的 `V0 + (A+g)dt`（加速度只算一次，不翻倍）；`processLanded`：`Floor = 法线`，
`Landed` 事件 → 当前 move 的 `Landed`（默认 `SetMove(Landing)`）→ 物理切到 Walking → **Acceleration 归一化为单位长度**
→ 帧内剩余时间继续走 walking。`EnterFallingHeight` 在 `Landed` 之后才重置，所以 Landing 还能看到起跳高度。

**跳跃**（`TdMove_Jump.StartMove`）：`PreJumpMomentum = |V.xy|`；已经在向前移动时加 100 前向速度；
`Vz = 630 × GetMobilityMultiplier()`（重武器 430），`Pawn.JumpZ` 不被使用；`IsOkToJump` 是恒返回 false 的空桩。
平地跳顶点 630²/3200 = 124 uu，滞空 2·630/1600 = 0.7875 s。

## 15.8 动作框架与自动转移 `[ME:CONFIRMED decompile]`（找手撑点部分 `emulated`）

**帧内顺序**：控制器（输入 → `SetInputHint` → `PlayerMove` 设加速度 → `CheckCrouch` / `CheckJumpPressed` /
`CheckJumpReleased`，动作立即仲裁并 `SetMove`）→ Pawn 的脚本 Tick 与 Actor 计时器（`SetMoveTimer`）→
`performPhysics`：当前 move 的 **`CheckAutoMoves`**（槽 0x124），然后（重新读取当前 move）**`PrePhysics`**（槽 0x118），
然后物理 → `TickSpecial`：`EvadeTimer`、`bIllegalLedgeTimer` 倒数，`bUncontrolledSlide` 强制 RumpSlide，
当前 move 的 **`TickMove`**（槽 0x11c：`Timer` 倒数、`MoveActiveTime += dt`）。
所以新 move 第一次 `CheckAutoMoves` 时 `MoveActiveTime == 0`。

**`CheckAutoMoves`**（只有 TdPhysicsMove 系有；Walking、Crouch、Slide、Landing 没有任何原生自动转移）：

| # | 开关 | 检查 | 结果 |
| --- | --- | --- | --- |
| 0 | — | 速度三个分量都 < 1e-4，或持重武器 | 什么都不做 |
| 1 | `bCheckForWallClimb` | `WallRun.CanDoMove()`（不受延迟限制） | 墙跑（左/右） |
| 2 | 任一开关，且 `MoveActiveTime > bDelayTimeCheckAutoMoves` | 找手撑点 → 0 无 / 1 只有墙 / 2 有可抓的顶 | — |
| 3 | `bCheckForWallClimb`，结果 ≥ 1 | 需要输入提示 Up、2D 距离 ≤ 120、正在上升、入射 ≤ 33°、若有顶则顶高 ≥ 180 | 垂直蹬墙 |
| 4 | 结果 = 2 | `FoundReachableHandPlant`，`bFoundLedge = true` | — |
| 5 | `bCheckForVaultOver` | `AutoStepUp.CanDoMove()` | AutoStepUp |
| 6 | `bCheckForVaultOver` | `VaultOver.CanDoMove()` | VaultOver |
| 7 | `bCheckForGrab` | IntoGrab 原生检查（够取 200 × 接近速度系数、顶面法线 Z ≥ 0.707、70° 以内） | IntoGrab |

**`PrePhysics`**：精确定位插值；然后 `bCheckForSoftLanding`（Vz < −400 且 2 s 后的落点是软着陆材质）→ SoftLanding；
`bCheckExitToFalling`（Vz < `ExitToFallingZSpeed`）→ Falling；`bCheckExitToUncontrolledFalling`（已下落超过
`FallingUncontrolledHeight`）→ FallingUncontrolled。

**`RedoMoveTime` 只在脚本 `CanDoMove` 里检查**，原生的蹬墙、抓边检查都不看它。

**找手撑点**：在脚底上方 112 的手高处，向前扫两个相距 50 的 10×10×160 盒子，两次结果一致才算数；
原版的左右两组侧向检测**永远不可能通过**（同时要求法线 Z ≥ 0.98 和 ≤ 0.2），模拟器证实了这一点。照原样保留。

**`bIllegalLedgeTimer`**（墙跑跳设 2 s，进入 Walking 清零）：期间禁止对刚离开的那面墙（法线夹角 11.5° 以内）
抓边、蹬墙、翻越，禁止向前墙跑上同一面墙；侧向墙跑反而禁止的是**正对面**那面墙。

**`MoveActionHint`**：每帧由**原始轴**（屏蔽输入之前）计算：前后超过 0.8 为 Up/Down，左右超过 0.3 为 Left/Right
（覆盖前后），超过 0.96 记 `bMax`。墙上（PlayerWallWalking）左右门槛提到 0.8，非 Up 的提示清空。

**小函数**：`FloorDeclineTooSteep` 即 `Floor.Z < 0.72`；`TestCanUnCrouch` 向上扫一个完整站立盒子 58 uu
（实际只需要 29，原样保留）；`IsLandingOnSoftObject` 是向下的短探测，要求法线 Z > 0.9 且为软着陆材质。

**对语料的更正**：`TdMove_Walking` 继承自 TdPhysicsMove，不是 TdMove（06）；`bCheckForEdgeInVelDir`
只是把速度方向的竖直分量加进手撑点探测方向（06）；`TdMove_WallKick` 恒不可用（04 §4.3 的"覆盖还是叠加"已无意义）。

## 15.9 地面物理 `[ME:CONFIRMED emulated]`（CalcVelocity、坡度摩擦、三个小函数；其余 `decompile`）

**坡度摩擦**（physWalking 开头，用上一帧的速度和地面法线）：
`uphill = −(SafeNormal2D(Floor) · SafeNormal2D(V))`，`slope = sin(坡角) × uphill`；
`WalkFric = (Upward|DownwardWalkFrictionScale × slope + 1) × move.FrictionModifier`，钳制在 [0.4, 2.0]；
Slide、RumpSlide、MeleeSlide 改用 Slide 的缩放（5.0 / 1.8），**不钳制**，可以为负。

**CalcVelocity**（TdPawn 自己的版本）：`CalcVelocity(AccelDir, dt, GroundSpeed, GroundFriction × WalkFric, 刹车)`，
`m = 机动性倍率 × move.SpeedModifier`。
- 加速度上限 `AccelRate × m`（6144 × m）。
- 有输入：`V −= V·dt·Friction·0.1`，各方向一样，**没有 UE3 的转向摩擦**，转向全部来自 15.2 的加速度函数。
- 加速度为 0（刹车）：30 ms 切片，`V −= V·2·slice·Friction·BrakingFrictionStrength(0.5)`，反向或低于 10 uu/s 时归零。
- 然后 `V += A·dt`，`|V|` 上限 `GroundSpeed × m`。精确定位中的 move 跳过上限、阻力和刹车。

15.2 里那一项 `+ V·GroundFriction·0.1` 只在 `WalkFric = 1`（平地）时正好抵消阻力；坡上的净效果是
`0.1·GF·(1 − WalkFric)·V`：上坡变慢、下坡变快。直着冲下超过 33.7° 的坡时滑铲摩擦为负，速度逐帧增长到上限。
滑铲用刹车分支：2 × 0.5 × 0.8 = 0.8/s，与语料实测 0.79/s 吻合。

**physWalking 一帧**：Vz、Az 置零 → CalcVelocity → 子步（≤ 0.05 s，最多 8 次）：边缘检查（只触发 Vertigo
和 0.2 s 的 SlideOffLedge 计时；只有 Crouch 会真的在边缘停下）→ 前进（上坡超过 11.5° 时跳过普通前进，直接 stepUp：
上 37、前进、下 37）→ 撞墙且夹角小于 45° 时保留全部剩余距离沿墙走（**不损速**）→ 37 uu 向下扫找地面 → 贴地到
地面上方 2.15 uu → 没有可走的地面就走出边缘：`setPhysics(Falling)`、`SetMove(Falling, 检查 CanDo)`，剩余时间交给 falling。
帧末（除非瞬移）`Velocity = 实际位移 / dt`，Z = 0。

**边缘检查**（`EdgeCheck` 0x012b8a30、`CheckValidFloor` 0x012b6ac0 及其探测 0x012b5eb0，`decompile`）：
`EdgeCheck` 从身体中心高度向下打三条线，深 `H + 36 + 4`：子步末端再往前 20，以及左右 45° 两条对角
（未归一化的对角向量 × `|Delta|·0.7071 + 20`）。落点低于脚底超过 MaxStepHeight 或法线不可走即"无地面"；
中心加右前、或三者中恰有两条无地面时启动 0.2 s 的 `SlideOffLedge`（已在跑则不重启）。速度超过 300 或提示前/后时
原样返回。否则在脚底下方 8 uu 处从外向内横扫，找到边缘立面后去掉 Delta 指向立面的分量（离立面足够近时）；
两条对角都悬空的外角分别扫两面，按距离裁一面、另一面或直接归零。`CheckValidFloor` 在脚底（坡面上再压低半径
× 坡度）沿前进方向和横向各做一次前后对扫，找"中心已越过 10 uu 以上"的边缘立面，算出把方盒推离立面的位移，
再从推后的位置向下扫 MaxStepHeight + 2；找不到可站的地面即无效，带推开参数时真的推过去并设 `EvadeTimer = 0.2`。
`SlideOffLedge`（脚本）在 `bAvoidLedges`（玩家默认 true）、move 也避边、地面可走时调用它，无效就进 Falling。
落地边缘检查（N2 §2c）：非失控下落中，硬着陆（落差 > 530、落在排除手脚的表面、或 180TurnInAir）时用推开版检查，
无效则重启计时、本子步不落地并把剩余位移再走一次（`retry` 在循环里不清零，第二次碰到地面也不落地）；
其他落地只在无效时重启计时，照常落地。

**UpdateWalkingState**：按 |V.xy| 严格小于 5 / 50 / 260 / 400 / 630 分为 Idle / Sneak / Walk / Jog / Run / Sprint。

## 15.10 墙面物理 `[ME:CONFIRMED emulated]`

Physics 12 跑 `physWallRunning`，13 跑 `physWallClimbing`；两种模式下 `Floor` 存的都是墙法线；
墙上的控制器状态把 `Acceleration` 设为 0，**玩家输入推不动人**。`Moves[4]`、`Moves[5]`、`Moves[40]` 是同一个
`TdMove_WallRun` 对象。

**进入墙跑**：`FindWallForward` 要求身体朝向与墙法线成 33°–90°（即与墙面 ≤ 57°），探测长度
`50·(1 + 0.8·max(|V.xy| − 400, 0)/320)`，还要有约 190 uu 高的墙；左右由叉积符号决定。`FindWallSide`
只在起跳点 30 uu 以内、有横移提示时用，墙法线要在侧向 60° 以内。

**每帧**：
1. 物理前：V.xy **瞬间**对齐到沿墙切线方向，大小不变（没有对齐速率）。
2. 摩擦 0.05；加速度 `(0, 0, −820·(1+n))`（上升时）或 `(0, 0, −500·(1+n))`（下落时），n 为连续墙跑次数。
   语料里的"Horisontal 加速度/减速度"其实是**墙上的竖直重力**。
3. Vz < −500 结束（`FallingOffWall` → Falling）。
4. CalcVelocity：`V.xy −= V.xy·0.05·dt`（Z 不受摩擦），`V += A·dt`；移动；向前 35、向墙内 37 探测，并把身体
   往墙里推 37 保持贴合；身体朝向跟随墙法线变化；实际位移速度更慢时才替换 V。

墙跑**没有水平最低速度，也没有时间上限**。墙到头、墙向外折超过 16°、内角超过 66°、头顶被挡 → Falling 物理；
碰到地面 → Walking 物理，再进 Landing。60 Hz 仿真：0.64 s 到顶，1.65 s 脱离，与实测一致。
`StartMove`：`BeginSpeed = |V.xy|`（上升时至少 300）；上升且不是连续墙跑时 `Vz = sqrt(2·820·h)`，
`h = min(170, 头顶净空) − (Z − LastJumpZ)` 取整——170 是相对起跳点的墙跑顶点高度。

**垂直蹬墙**：进入要求输入提示 Up、**镜头**朝向与墙法线在 33° 以内、正在上升、2D 120 以内、顶高至少高出脚底 180。
`ReachedWall`：`AddOnHeight = 60·clamp((入墙速度 − 400)/250) + 130·clamp(Vz/320)`，`Vz = sqrt(4·AddOnHeight·800)`。
每帧把 V 投影到墙面，XY 摩擦 6，加速度 `(0, 0, −g)`；**帧末同样 `V = 2·Vnew − V0`**，所以有效重力 1600、
水平摩擦约 12/s，正好上升 `AddOnHeight`（最多 190 uu）。Vz < 0 或墙消失时结束。
`CheckDoubleJump`：找到手撑点、Vz < 100、顶面低于 `GroundZLoc + 480` 时，`Vz = sqrt(4g·(EdgeZ − 头顶Z + 4))`。

对语料的更正：`AlignSpeed (700)`、`VelocityStartLimit (300)` 只是 `FindWallSide` 里探测方向的权重；
`InitialZHeight` 是初始竖直速度的来源而非位置抬升；57° 和 60° 属于两个不同的探测，不是滞回区间；
垂直蹬墙的"Vertical friction"只作用于 XY，重力实际是 1600。

## 15.12 梯子、移动体积样条、根运动与收尾 `[ME:CONFIRMED decompile]`（梯子步位另经关卡数据复核）

### 梯子（TdLadderVolume）

- **步位在加载时由刷子生成**（原生 `0x012ab620`，非编辑器专属）。设 `Start` / `End` 为体积中心正下 / 正上方的底面 / 顶面点
  （边界追踪报告的点在面外 1 uu），`MoveDirection` 为体积的 Z 轴：
  `S = (从 Start + MoveDirection·32 沿 WallNormal 找到的攀爬面) − WallNormal·64`；`TopZ = 顶面.z − 96`；
  `n = trunc(min(TopZ − S.z, 10000) / 32)`（**截断**，不是四舍五入）；第一步在 `TopZ − n·32`，之后每 32 uu 一步直到 `TopZ`。
  所以最高一步在顶面下 96 uu，最低一步在 `Start` 上方 32～64 uu。
  用这条公式重算 123 个原版梯子的 `PawnLadderLocations`：88 个与烘焙数据完全一致；其余都是烘焙的 Start/End 为 NaN、
  偏离上亿 uu，或刷子不是长方体。改用四舍五入只有 57 个一致。
- `GetLadderLocation(i)`：`i` 夹到 `[0, 步数−1]`（不是 `GetLastStep`）；身体在步位沿 WallNormal 外移 50 uu（管子 62），
  管子再低 5 uu。常见的 128 uu 深体积里步位本身在中心线外 1 uu，所以身体离中心线 51 uu。
- `GetClosestStep(z)`：**所有**步位中高度最接近的一个，平局取下标小的；`GetClosestStepUp`：第一个高于 z 的，否则最高一个；
  `GetClosestStepDown`：从 `GetLastStep` 往下第一个低于 z 的，否则 0；`GetLastStep`：梯子取最高一步，管子取最高一步下数第三步。
- IntoClimb 判断"在梯顶之上"和梯顶进入时用的是 `PawnLadderLocations.Length − 1`（真正最高的一步），管子也一样。

### 移动体积样条（TdMovementVolume）

- 样条是以 `Middle` 为控制点的**二次 Bezier**：`P(t) = Start·(1−t)² + Middle·2t(1−t) + End·t²`，`t` 夹到 0..1；
  `GetSlopeOnSpline(t)` 是 `(Middle−Start)(1−t) + (End−Middle)t` 的单位向量。`SplineLocations` 是它在 `t = i/N`
  （`N = NumSplineSegments`，默认 10）的采样，只在编辑器里生成、随关卡烘焙。
- `FindClosestPointOnDSpline(P, out C, out T, Hint = −1)`：只在前 `N` 个采样点里找（**终点从不是候选**）；给了 Hint 就从 Hint
  向前、向后各做一次下降搜索；然后取指向较近邻点的那一段，**不夹取**地投影（C 可以落到线段之外），
  `T = 段号 + clamp(|s|, 0, 1)`——落在段起点之后的点 `s < 0`，却按正值计入。
- Balance / LedgeWalk 用 `T / NumSplineSegments`、IntoZipLine 用 `T / (SplineLocations.Length − 1)` 求坡度；
  LedgeWalk 的 `CurrentParamOnCurve` 从不重置，下一次沿墙走从上一次停下的段开始搜。

### 根运动

- **动画更新**（`UpdateSkelPose`，在本帧物理之后）：根运动开着且有根运动动画在播时，把这一帧根骨位移按网格**当前**的
  世界变换转到世界，**累加**进 `RootMotionDelta`；没有根运动动画或根运动关着时清零。
- **物理取用**（`APawn::CalcVelocity`，TdPawn 只要根运动开着就交给它）：只有上一次动画更新时根运动已经开着
  （`PreviousRMM`）才取用——**开启根运动的那一帧仍走引擎自己的常规速度计算**（UE3 的方向摩擦，没有机动性和 SpeedModifier）。
  取用时 `Velocity = Delta / dt`（三维），`Acceleration = Velocity / dt`，然后清空 Delta；walking 只走水平部分，flying 走三维；
  falling 自己处理：只取水平部分，丢掉加速度，跳过空中操控上限，竖直方向照常受重力。
  `RootMotionScale` 只有 StepUp 的不可达分支会改。
- **根旋转带着视角走**：每一帧根旋转转动 Pawn 时，控制器的偏航被直接设成 Pawn 的偏航（俯仰不变）。
  这回答了"原版视角是否跟随根旋转"：跟，而且是逐帧对齐。180Turn 之后 `FaceRotation` 让 Pawn 回追视角，正因为视角已经转过去了。

### 其余

- `TdPawn.FaceRotation` 下落分支算出的"每秒 5 倍缓动"写进了一个之后不再使用的变量：**是死代码**，空中和地面一样直接对齐视角偏航。
- GrabTransfer 的 `LadderTransfer` 在提示 Up 时，方向变量从未写入，取的是脚本虚拟机先前留在 C 栈上的数据，
  无法从代码确定 `[ME:UNKNOWN]`；按其他提示：右 / 左是 Pawn 的 ±Y 轴，无提示是**控制器**旋转的朝向。
- 疼痛体积（铁丝网、电网，`PhysicsVolume.bPainCausing`）在 `PostBeginPlay` 生成一个每秒触发一次的计时器，
  按**体积自己的时钟**伤害当时在里面的所有人；进入时的那一下伤害来自 `Touch`。
