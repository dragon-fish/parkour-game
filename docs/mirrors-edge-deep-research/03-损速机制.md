# 03 · 损速机制

← [README](README.md) · 上一篇 [02-速度系统](02-速度系统.md)

如果说 [02](02-速度系统.md) 讲的是"速度怎么来"，这一章讲的是"速度怎么没的"。**镜之边缘的技巧深度几乎全部来自这一章**——跑酷的本质不是加速，是**不减速**。

---

## 3.1 落地损速

✅ **确证** — `TdMove_Landing` CDO：

| 参数 | 值 (uu) | 公制 | 含义 |
|---|---|---|---|
| `SkillRollLandingHeight` | 200 | 2.0 m | 超过此坠落高度，可用 roll 化解 |
| `SoftLandingHeight` | 300 | 3.0 m | 软着陆上限 |
| `HardLandingHeight` | 530 | 5.3 m | 硬着陆阈值 |
| `HardLandingDamage` | 15 | — | 硬着陆扣血 |
| `LandingSpeedReduction` | 65 | — | 落地减速量（单位见下） |

🔶 **推导** — 对应的落地垂直速度（`v = √(2gh)`，g = 800）：

| 高度 | 落地垂直速度 |
|---|---|
| 200 uu | 566 uu/s |
| 300 uu | 693 uu/s |
| 530 uu | 921 uu/s |

于是得到**三段式坠落判定**：

```
坠落高度 < 200 uu (2.0 m)     → 无惩罚，直接接着跑
200 ~ 300 uu (2.0 ~ 3.0 m)    → 软着陆，roll 可完全化解
300 ~ 530 uu (3.0 ~ 5.3 m)    → 需要 roll，否则损速
> 530 uu (5.3 m)              → 硬着陆：扣 15 血 + 强制减速动画
```

⚠️ **`LandingSpeedReduction = 65` 的单位未确证。** 三种可能：损失 65%、保留 65%、减去 65 uu/s。二进制数据回答不了这个问题（需要字节码）。📣 社区普遍描述硬着陆是"速度几乎归零"，倾向于"损失 65%"或更激进的解释，但无人给出精确数值。这是本手册最重要的一处 ❓。

### 关于 Roll

✅ 确证的相关参数：

```
TdPawn.RollTriggerTime                    = 1.0     ← 见下
TdMove_Falling.RollLandingTimeThreshold   = 2.0
TdMove_Falling.MaximumSpeedForRollLanding = -5000
TdMove_Falling.EnterToFallingZSpeed       = -200    ← 进入 Falling 状态的下落速度阈值
```

⚠️ `RollTriggerTime = 1.0` 推断为**输入预缓冲窗口 1 秒**——即落地前 1 秒内按下蹲都会被记录并在触地时触发 roll。若属实，这是一个**极其宽容**的 jump-buffer（对比多数动作游戏的 0.1–0.2 s）。这与 📣 社区"skill roll 时机很宽松、难的是知道该不该 roll"的普遍感受一致，但未经字节码验证。

⚠️ `MaximumSpeedForRollLanding = -5000` 推断为：下落速度快于 5000 uu/s 时 roll 失效（必死）。5000 uu/s 对应坠落高度 15625 uu = 156 m。

📣 **社区补充（重要）**：ME1 的 skill roll **本身会损速**，但**只在翻滚后继续向前移动时才掉速**。这解释了为什么速通里 roll 后常接侧向或跳跃输入。Catalyst 取消了 roll 的损速，是两作手感差异的关键之一（见 [07-Catalyst对照](07-Catalyst对照.md)）。

### ❓ 一处数据矛盾

`DefaultGame.ini` 中 `FallingUncontrolledHeight = 1000` 上方有 DICE 留下的注释：

```
# 1600 is the downward speed after falling 780 cm
# 2002 was the previous Speed we needed
```

按 `g = 800` 计算，坠落 780 uu 的末速应是 1117 uu/s，不是 1600；反过来 1600 uu/s 对应的坠落高度是 1600 uu 而非 780。**注释与当前重力值对不上**，最可能是重力调整后注释没更新的历史残留。同时参数名叫 `Height` 但注释在讨论 `Speed`，语义存疑。这条不要采信。

## 3.2 转向损速

✅ **确证**：`TdPawn.SpeedTurnDecelerationFactor = 10`

⚠️ 语义推断：转向时按转角速率乘以该系数扣减速度能量。**没有找到"超过 N 度开始掉速"的角度阈值参数**——这暗示转向损速是**连续函数而非阈值判定**：转得越急，掉得越多，没有免费额度。

📣 **社区实测的「3-step Rule」**：跳跃落地后必须先直行约 3 步再开始转向，否则会掉速。这条规则由 PC 版玩家发现。

⚠️ 我的解读：这更可能不是一条独立规则，而是 3.1 的落地损速 + 3.2 的转向损速**叠加**的结果——落地瞬间速度能量已经受损，此时再叠加转向扣减就跌破了某个动画/状态阈值。3 步 ≈ 0.5 秒，恰好是速度能量在 `SpeedEnergyDecelerationTime = 3` 的衰减节奏下恢复一档的量级。**这是推断，未验证。**

### 180° 急转

✅ `TdMove_180Turn`：`FrictionModifier = 0.3`、`TurnTime = 0.25`、`RedoMoveTime = 0.5`

急转期间摩擦力降到 30%（**减少**损速，是个保速设计），耗时 0.25 秒，0.5 秒内不能再次触发。

## 3.3 摩擦力模型

✅ **确证** — `TdPawn`：

```
UpwardWalkFrictionScale    = 1.1     ← 上坡摩擦力更大
DownwardWalkFrictionScale  = 0.8     ← 下坡更小（更容易加速）
MinWalkFrictionModify      = 0.4
MaxWalkFrictionModify      = 2.0
UpwardSlideFrictionScale   = 5.0     ← 上坡滑铲摩擦力 5 倍，几乎立刻停住
DownwardSlideFrictionScale = 1.8
BrakingFrictionStrength    = 1.0     (TdPlayerPawn 覆写为 0.5)
```

**设计意图很清楚**：地形坡度直接调制摩擦力，下坡是"免费加速带"，上坡是"税"。滑铲的坡度敏感度（5.0 vs 1.8）比走路（1.1 vs 0.8）夸张得多——所以下坡滑铲飞快、上坡滑铲原地卡住。

`TdPlayerPawn` 把 `BrakingFrictionStrength` 从 1.0 降到 0.5：**玩家比 AI 更难刹住车**。这是刻意让玩家"滑"起来。

## 3.5 绕过损速的社区技巧（机制原理）

这些是速通社区发现的、能规避落地损速的手段。它们**不是纯 bug，而是判定系统的可预期副作用**——理解它们才能理解原系统的判定边界。

| 技巧 | 机制原理 | 可信度 |
|---|---|---|
| **Ventkick** | 垂直下落中踢击可**重置累计坠落高度计数**。仍受坠落伤害，但不触发落地减速 | 📣 社区一致 |
| **Kickglitch** | wallrun 中单腿踢会在脚下生成持续 **1–3 帧**的实心不可见平台，落上去即重置下落高度；时机准确还能再次起跳形成二段跳 | 📣 社区一致，帧数有 1–2 与 3 两种说法 |
| **Drop-Roll** | 在平台边缘完成 roll 动画后立刻掉出边缘，重置下落高度。说明 **roll 的高度重置在动画结束时结算**，而非落地瞬间 | 📣 社区一致 |
| **Fall-Break Kick** | 垂直下落时踢击可替代 roll 规避硬着陆 | 📣 社区一致 |

**共同结论**：一代把「坠落伤害」和「落地减速」实现为**两套可分离的判定**，且都基于"上一次触地以来的累计下落高度"这一可被重置的计数器。任何产生触地事件的东西（隐形平台、roll 动画结束）都能重置它。

**对 Godot 复刻的启示**：如果你把落地惩罚实现为"读取当前 `velocity.y`"，就得不到这些涌现行为；实现为**"自上次触地以来的累计下落高度"计数器**，才能复刻出这一整层技巧空间。这是本手册中最值得抄的一个实现决策。

## 3.6 ⚠️ 帧率相关性

📣 **社区（PCGamingWiki）**：ME 的移动物理**与帧率相关**。默认锁 62 FPS（`bSmoothFrameRate=TRUE`、`MaxSmoothedFrameRate=62`）；帧率升高会同时提高玩家 friction，改变部分移动机制的速度；超过 150 FPS 后下坡滑铲几乎无法控制。

这是 UE3 变步长物理的典型症状。**Godot 用固定 physics tick 会得到与原作不同（但更稳定）的行为**——这是移植时必须接受的偏差，见 [09-Godot移植指南](09-Godot移植指南.md)。
