# 10 · 「镜之边缘-like」判定标准

← [README](README.md) · 上一篇 [09-Godot移植指南](09-Godot移植指南.md)

前面九章是证据，这一章是结论：**哪几条机制去掉之后就不再像镜之边缘，哪些只是外观。**

判定依据尽量落在 [02](02-速度系统.md)–[06](06-Move状态机架构.md) 的确证数据上，而不是体感。[07-Catalyst](07-Catalyst对照.md) 提供了一个天然的对照实验——**同一个 IP、同一个工作室、削平惩罚系统之后，玩家不再认为那是镜之边缘的手感**。

---

## 10.1 本质机制（去掉就不像了）

### ① 速度是一条要花很久才能爬满的曲线

✅ 7 秒才能从 0 到 720 uu/s，前 0.4 秒就拿到 55% 而后 45% 要花 6.6 秒。

**这是第一判据。** 如果你的角色按住 W 两秒就到满速，无论其他做得多像，它都不是镜之边缘——因为**速度不再是需要经营的资产**，玩家也就没有东西可以失去。所有损速机制的意义都建立在"速度很难挣"之上。

### ② 空中不限速 + 极低空中操控

✅ `AirSpeed = 2400`（地面上限的 3.3 倍，实质不限）+ `AirControl = 0.025`（引擎默认的一半）。

**起跳前的速度被完整带走，起跳后几乎无法修正。** 这两条合起来，把"起跳的那一瞬间"变成了游戏里最重要的时刻。如果空中能自由调整方向，跑酷就退化成飞行。

### ③ 损速无处不在，且是连续函数

✅ 落地（三段阈值）、转向（`SpeedTurnDecelerationFactor = 10`）、翻越高障碍（钳到 200–400）、踢击、持枪（上限砍到 55.6%）、平衡木（×0.34）、下蹲（×0.4）。

关键在于**转向损速没有"免费额度"**——找不到任何"超过 N 度才开始掉速"的阈值参数，它是连续的。**每一次转向都在花钱**，玩家因此被迫规划路线而不是即兴反应。

⚠️ **这一条是 Catalyst 丢掉的东西**，也是社区说它"像 UFO"的机制根源。

### ④ 技巧梯度写在动作参数里

✅ `WallRunningPushAwaySpeedNoob = 120` → `ProAdd = 400`（4.3 倍区间）；`DodgeJumpInertiaConservation` 0.3 vs 1.0。

**同一个按键，执行质量决定回报，跨度要足够大。** 不靠额外按键、不靠 QTE、不靠教学关。DICE 直接把 `Noob`/`Pro` 写进了变量名——他们非常清楚自己在做什么。

没有这一条，游戏对新手和高手是同一个游戏，也就没有"越玩越快"的成长曲线。

### ⑤ 落地惩罚基于可重置的累计下落高度

✅ 判定基于"自上次触地以来的累计下落高度"，而非当帧垂直速度；⚠️ 且伤害与减速是**两套可分离的判定**。

这是一个**实现细节**，但它涌现出了 ventkick、kickglitch、drop-roll 一整层速通技巧（[03.5](03-损速机制.md#35-绕过损速的社区技巧机制原理)）。**这层技巧不是设计出来的，是从正确的实现方式里长出来的。**

如果你读 `velocity.y`，这一整层永远不会出现。

### ⑥ 少量按键 + 上下文解析

✅ 114 个 Move 类，输入层只有 **2 个上下文动作键**（`GBA_Jump` 向上、`GBA_Crouch` 向下）+ 1 个走路修饰键。没有独立的 wallrun / vault / roll / coil 键。

📣 记者试玩后写道：「整段 demo 我只用了三个按键。」

**复杂度必须在上下文解析里，不能在按键组合里。** 一个需要背组合键的跑酷游戏不是镜之边缘。

### ⑦ 显式的动作状态机

✅ 每个动作是独立的类，声明自己的速度倍率、摩擦倍率、**镜头约束范围**、环境探测策略、动画混合、冷却时间。

⚠️ 尤其是**镜头约束**：wallrun 时视角被硬锁在 pitch ±71.4°、yaw ±90°。"贴墙时镜头自动看向前进方向"不是动画效果，是**输入约束**。

### ⑧ 第一人称

📣 开发者一手：「一旦变成第三人称，你就是在**看** Faith，而我们希望你与她**连接**。」

DICE 从未考虑过第三人称。这条不需要论证。

### ⑨ 跳跃是「短而可控」，不是「低重力长滞空」

✅ 重力 **16.0 m/s²**（真实值的 1.63 倍）、起跳 **6.3 m/s**、滞空 **0.79 秒**、
跳跃最高点 **1.24 m**、满速平跳约 **6.5 m**（逐帧实测，见
[02.4](02-速度系统.md#24-重力与跳跃)）。

📌 **本条此前的表述完全反了**，必须记下来：旧版按配置的 `g = 800` 与 `BaseJumpZ = 560`
推算，得出「重力只有真实值的 82%、滞空 1.40 秒、跳远 10.1 m」，并把「从容感来自低重力
长滞空」列为 ME 的本质特征之一。实测把它推翻了——**ME 的重力比现实还大 63%，滞空只有
0.79 秒，比多数 FPS 更短促。**

那么那种从容感来自哪里？来自**空中不给你修正机会**（`AirControl = 0.025`）和
**水平速度被完整保留**（`AirSpeed = 2400`，几乎不限空中速度）。**起跳质量决定一切**，
落点在离地那一刻就写死了——这种「一锤定音」的确定性被体验为从容，而不是滞空长度。

⚠️ 跳跃最高点 1.24 m 距翻滚阈值（2.00 m）有 38% 余量：平地跳跃不触发翻滚，
也不产生落地惩罚。（旧版称二者「只差 4 cm、是刻意的调校痕迹」——那是错误重力制造的
幻觉。）结论不变：**跳跃高度与落地阈值必须成组校准**，否则每跳一次都掉速。

### ⑩ 移动系统就是战斗系统

✅ 每个 Move 都声明 `AiAimPenalties` 与 `AiAimOneShotPenalties`：wallrun 时敌人瞄准难度 `(0.4/0.5/0.7)`，动作开始瞬间还会一次性扣掉敌人 75–200 点精度。

**「跑得漂亮」直接等于「更难被打中」。** 移动不是战斗的准备阶段，它**就是**战斗。这一层很多复刻会漏掉。

## 10.2 表层装饰（可以完全不同）

| 元素 | 为什么是装饰 |
|---|---|
| **速度驱动的 FOV** | ⚠️ **ME 根本没有**。固定 90°，唯一的动态 FOV 是恐高时**缩小**到 84°。这是现代跑酷游戏的通用语汇，不是镜之边缘的 |
| **Head bob** | ⚠️ DICE **在开发中移除了它**，目标重述为「从你的**眼睛**看世界，而不是从你的**头**」 |
| **红色 Runner Vision** | 是**可读性**方案，不是移动机制。可以用任何别的方式解决"高速下看懂环境"的问题 |
| **白色 + 亮色点缀的城市美术** | 服务于 Runner Vision 的可读性，与移动手感无关 |
| **看得见自己的脚** | DICE 做了整套腿部交互系统，**因工期不足在发售版关闭了**。开发者强调的是反射与影子里的"惊鸿一瞥"，不是持续的全身可见 |
| **具体动作库规模** | swing / zipline / springboard / balance 都可增可删。ME 自己就把 springboard 做成了速通里常被跳过的动作 |
| **无 HUD** | 是上面那些的结果，不是原因 |

## 10.3 中间层：重要但可替换

这些不是本质机制，但它们承担了"把物理翻译成感受"的工作，删掉会明显掉档，换个实现方式则无妨：

- **Wallrun 时的 camera roll**
- **落地 dip**（ME 的一手准则：「大脑预期什么发生，就必须发生」——坠落时画面**必须**晃）
- **Roll 的芭蕾 spotting 镜头**：头部甩转后回到与触发前**完全相同**的注视方向，而不是自由跟随身体旋转
- **中央焦点白点**：作为防晕锚点，"部分绑定摄像机 + 由远处焦点控制"
- **局部重力修改**：swing 脱手后 0.7 秒内重力降到 73–75%，coil/barge 的 `HeightBoost`——ME 反复用这招做手感补偿

## 10.4 速查清单

给你的项目当验收表用：

| # | 判据 | 本项目现状 |
|---|---|---|
| 1 | 满速需要 5 秒以上持续奔跑才能达到 | ❌ 缺失（`sprint_speed` 是常数） |
| 2 | 空中不限速 + 空中操控很低 | ⚠️ 部分（`air_max_speed = 9.0` 有限速） |
| 3 | 转向连续损速，无免费额度 | ❌ 缺失 |
| 4 | 落地/翻越/踢击都在扣速 | ⚠️ 部分（vault 有损速，转向没有） |
| 5 | 关键动作有 3 倍以上的执行质量梯度 | ❌ `wall_jump_push` 是常数 |
| 6 | 落地惩罚基于可重置的累计下落高度 | ❌ 基于当帧速度 |
| 7 | 只用 2–3 个上下文动作键 | ✅ 已符合 |
| 8 | 显式状态机 + 每状态声明镜头约束 | ✅ 架构已有；⚠️ 镜头约束未按状态区分 |
| 9 | 第一人称 | ✅ |
| 10 | 低重力长滞空（平地跳滞空 ≈1.4 s） | ❌ 当前 0.63 s |
| 11 | 移动质量影响战斗（敌人瞄准难度） | ❓ 视项目是否有战斗 |

**优先补 1、5、6**——它们分别是"速度是资产"、"技巧有梯度"、"技巧能涌现"的三个支点，且改动成本都不高。详见 [09.3](09-Godot移植指南.md#93-建议的实施顺序)。

---

## 10.5 一句话定义

> **镜之边缘-like = 速度是一种需要长时间积累、极易失去、且失去方式远多于获得方式的资产；玩家的全部技巧在于用正确的动作把损失降到最低；而每个动作的回报跨度大到足以区分新手与高手——所有这些通过两个上下文按键、在第一人称下完成。**

其余都是装饰。
