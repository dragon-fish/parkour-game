# 02 · 速度系统

← [README](README.md) · 上一篇 [01-方法论](01-方法论与可信度分级.md)

这是整个手册最重要的一章。**镜之边缘的手感有一大半来自这一条曲线。**

---

## 2.1 速度曲线（核心）

✅ **确证** — 来自 `TdPawn` CDO 的 `SpeedCurve_LightWeapon`，类型 `InterpCurveFloat`，插值方式 `CIM_Linear`：

| X（速度能量 / 秒） | Y（速度上限 uu/s） | 公制 |
|---|---|---|
| 0.0 | 0 | 0 |
| 0.4 | 400 | 4.0 m/s |
| 1.0 | 520 | 5.2 m/s |
| 3.5 | 650 | 6.5 m/s |
| 7.0 | **720** | **7.2 m/s** |

分段线性，超过 7.0 后保持 720。曲线终点 720 与 `TdPawn.GroundSpeed = 720` 完全一致——`GroundSpeed` 就是这条曲线的天花板。

**形状解读**：前 0.4 秒极陡（0 → 400，占了 55% 的最终速度），之后急剧放缓。剩下 45% 的速度要花 6.6 秒去挣。这正是「起步很跟手，但越快越难快」的数学来源。

持重型武器时曲线塌成两点：

✅ `SpeedCurve_HeavyWeapon`：`0.0s → 0`，`1.0s → 400`。上限只有 400 uu/s（4 m/s），**只有徒手的 55.6%**。这是游戏在机制层面惩罚「捡枪」的方式——不是靠说教，是靠让你跑不快。

### 曲线的 X 轴是什么

⚠️ **推断**。参数命名指向一套"速度能量（speed energy）"系统：

✅ 确证的相关参数（`TdPawn` CDO / `DefaultGame.ini`）：

```
SpeedMaxBaseVelocity                  = 400
SpeedMinBaseVelocity                  = 10
SpeedWalkVelocityAccelerationFactor   = 7
SpeedSprintVelocityAccelerationFactor = 30
SpeedStrafeVelocityAccelerationFactor = 10
SpeedEnergyDecelerationTime           = 3
SpeedEnergyDecelerationExponent       = 0.5
SpeedTurnDecelerationFactor           = 10
```

⚠️ 合理推断：存在一个标量「speed energy」，向前奔跑时按 `AccelerationFactor` 累积、停止或转向时按 `DecelerationTime`/`Exponent` 衰减，再用它查这条曲线得到当前帧的速度上限。三个 `AccelerationFactor` 说明**侧移（10）积累速度比直跑（7）快、冲刺（30）最快**，或者反过来是不同状态下的除数——方向未经字节码验证。

⚠️ `SpeedEnergyDecelerationExponent = 0.5` 意味着能量衰减是**平方根型**而非线性——刚停下来时掉得快，接近零时掉得慢。或者相反，取决于公式写法。

❓ **未验证**：能量的具体累积公式、单位、以及 `SpeedMaxBaseVelocity=400` 在其中的角色（400 恰好是曲线上 0.4s 的值，也恰好是重武器上限，可能是"无能量时的基础速度"）。

---

### 🎯 交叉验证：曲线与社区实测精确吻合

这条曲线得到了两条**完全独立**的社区证据的确认（详见 [08-速通社区交叉验证](08-速通社区交叉验证.md)）：

| 社区说法 | 逆向数据 | 结论 |
|---|---|---|
| 「最高跑速 16 mph / 26 km/h」 | 720 uu/s = 7.2 m/s = **25.92 km/h = 16.10 mph** | ✅ 吻合到小数点 |
| 「从静止到全速冲刺要 7–10 秒」 | 曲线 X 轴终点 = **7.0 s** | ✅ 吻合 |

第一条同时**反向确认了单位换算**：只有在 `1 uu = 1 cm` 的前提下 720 uu/s 才等于 16 mph。UE3 官方文档明确说明单位比例因项目而异（UT 系列是 1 uu = 2 cm，"多数被授权方"用 1 uu = 1 cm），这条实测把 DICE 的选择钉死了。

## 2.2 离散速度档位

✅ **确证** — `TdPawn` CDO：

| 档位 | uu/s | m/s | 备注 |
|---|---|---|---|
| `SneakVelocity` | 5 | 0.05 | 潜行 |
| `WalkVelocity` | 50 | 0.5 | 走 |
| `JogVelocity` | 260 | 2.6 | 慢跑 |
| `RunVelocity` | 400 | 4.0 | 跑（= 曲线 0.4s 处） |
| `SprintVelocity` | 630 | 6.3 | 冲刺 |

⚠️ 这五个值更可能是**动画混合的阈值**（决定播放哪套 locomotion 动画）而非速度钳制值，因为实际上限由曲线决定。注意 630 同时也是 `BaseJumpZ` 的值，是巧合还是复用需要字节码确认。

## 2.3 基础运动属性

✅ **确证** — `TdPawn` CDO 覆写（括号内是 `Engine.Pawn` 的引擎默认值，用于对照 DICE 改了什么）：

| 属性 | 值 | 引擎默认 | 含义 |
|---|---|---|---|
| `GroundSpeed` | **720** | 600 | 地面速度上限 |
| `AirSpeed` | **2400** | 600 | 空中速度上限（放得极宽） |
| `AccelRate` | **6144** | 2048 | 加速度 uu/s²（引擎的 3 倍） |
| `AirControl` | **0.025** | 0.05 | 空中操控系数（**砍到一半**） |
| `CrouchedPct` | 0.4 | 0.5 | 下蹲速度倍率 |
| `BaseEyeHeight` | 76 | 64 | 眼高 |
| `MaxStepHeight` | 35 | 35 | 可直接迈上的台阶高度 |
| `WalkableFloorZ` | 0.71 | 0.70 | 可行走地面法线 Z 下限（≈ 44.8° 坡度） |

**三个最关键的改动**：

1. `AirSpeed = 2400` — 空中几乎不限速。所有的速度上限约束都在**地面**，一旦离地，你之前挣到的速度被完整保留。这是"跳跃能保速"的机制根源。
2. `AirControl = 0.025` — 极低。离地之后你几乎无法改变水平方向。**速度必须在起跳前挣好**，空中不能补救。这条与上一条配合，构成了"起跳质量决定一切"的设计。
3. `AccelRate = 6144` — 瞬时加速度很高，配合速度曲线的低上限，得到「立刻贴到当前上限，但上限本身慢慢涨」的手感。

⚠️ 注意 `DefaultGame.ini` 里另有一个 `AirControlAmount = 0.09`，是 `TdPawn` 自定义属性，与引擎的 `AirControl = 0.025` 并存。两者如何叠加未经验证。

## 2.4 重力与跳跃

✅ **确证**：

```
DefaultGravityZ = -800          (DefaultGame.ini / Engine.WorldInfo)
TdPawn.BaseJumpZ           = 560    ← 生效值，见下方实测
TdMove_Jump.BaseJumpZ      = 630    ← ❓ 未知在何种情况下生效
TdMove_Jump.BaseJumpZHeavy = 430    ← 持重武器
TdMove_Jump.JumpAddXY      = 100    ← 起跳附加水平速度
```

### ⚠️ 两个 `BaseJumpZ` 的冲突，及其实测解决

游戏里存在两个值不同的 `BaseJumpZ`：`TdPawn` 层是 **560**，`TdMove_Jump` 层是 **630**。二进制数据无法判定哪个生效。

📣 **游戏内实测**（Steam 正版，2026-08）：平地起跳、等高落地、落地前按下蹲键 → 触发**滑铲**而非**翻滚**。

翻滚未触发意味着坠落高度未达 `SkillRollLandingHeight = 200 uu`，由此反推起跳初速上界：

```
v₀ < √(2 × 800 × 200) = 565.7 uu/s
```

**560 落在界内（余量 5.7），630 远超。** 即使坠落高度计数是从进入 `TdMove_Falling`（`EnterToFallingZSpeed = -200`，前 25 uu 不计）才开始，630 的等效高度仍有 223 uu > 200，依然被排除。

**结论：生效值是 `560`。**

🔶 **推导**（标准抛体运动，忽略空气阻力）：

| 量 | 徒手 (560) | 持重武器 (430) |
|---|---|---|
| 上升时间 | 560/800 = **0.70 s** | 0.538 s |
| 跳跃最大高度 | 560²/(2·800) = **196 uu = 1.96 m** | 116 uu = 1.16 m |
| 平地总滞空 | **1.40 s** | 1.075 s |
| 满速平跳水平距离 | 720 × 1.40 ≈ **1008 uu = 10.1 m** | — |

**1.96 m 距离 2.00 m 的翻滚阈值只差 4 cm。** 这个 2% 的余量几乎不可能是巧合——DICE 刻意把平地跳跃卡在翻滚阈值**下方**：玩家自己跳起来落地，不应该被要求翻滚。参数之间的这种咬合是调校深度的直接痕迹。

滞空 1.40 s 仍是真人跑跳（约 0.65 s）的 **2.15 倍**，重力 8.0 m/s² 也低于真实的 9.81。这是**刻意的**：更低的重力 + 更高的起跳 = 更长的滞空 = 玩家有时间在空中判断落点。飘，但可控。

⚠️ `JumpAddXY = 100` 推断为起跳瞬间沿朝向附加 100 uu/s 水平速度——即"起跳本身给一点前冲奖励"。是加法还是设为最小值未验证。

⚠️ `Engine.Pawn.MaxJumpHeight = 96` 是 AI 寻路用的，不参与物理。

⚠️ **未找到** coyote time 或 jump buffer 的显式参数。`TdPawn.RollTriggerTime = 1.0` 可能是落地翻滚的输入预缓冲窗口（1 秒，相当宽容），但语义未验证 —— 见 [03-损速机制](03-损速机制.md#roll)。

## 2.5 对 Godot 实现的直接启示

不要用「加速度积分到最大速度」的常规写法。镜之边缘是**双层**结构：

```
第一层（快）：实际速度 --AccelRate=6144--> 当前上限        # 几乎瞬时
第二层（慢）：当前上限  <--SpeedCurve(energy)--  速度能量    # 需要 7 秒
```

玩家操作影响的是**第二层**（能量的累积与损失），第一层只是让角色紧贴上限、保持跟手。把这两层混成一层，手感就不对了。

具体写法见 [09-Godot移植指南](09-Godot移植指南.md)。
