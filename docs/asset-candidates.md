# 素材候选与授权记录

记录评估过的角色模型来源、授权状态，以及能不能真的用。**结论先行：目前没有任何一个可以直接集成，原因不是授权，而是格式与游戏视角。**

## 已评估

### Rossi（`C:\Users\xiaoy\Downloads\Rossi`）

- **格式**：Blockbench / YSM（Yes Steve Model），Minecraft 风格体素角色
- **构成**：`models/*.json`、`animations/*.animation.json`、`textures/texture.png`、`controller/controller.json`，共 3.3 MB
- **授权**：原作者允许**非商业**二次创作使用
- **可用性**：**几何与贴图可用，动画不可用**

动画不可用是硬事实，不是保守估计。`main.animation.json` 中有 61 个动画、**241 处 Molang 表达式引用**（`q.ground_speed`、`q.vertical_speed`、`q.anim_time` 及完整 math 库）。决定性证据：

```
run   | bones: 0  | length: None
walk  | bones: 27 | length: 1
```

`run` 没有骨骼、没有时长——它不是关键帧数据，而是**运行时用表达式计算骨骼变换的程序**。glTF 只能存烘焙关键帧，因此 Blockbench 导出 glTF 时这类动画必然丢失。

**但思路是可迁移的。** 这些 Molang 动画本质上是"由移动速度驱动的程序化动画"，而 spec 里 P5 的方案正是程序化 IK，同样由移动状态驱动。数据带不过来，但可以用我们自己的 `horizontal_speed()` / `velocity.y` 去驱动这个模型的骨骼。工作量不小，属于 P5 之后的选项。

### 模之屋（MMD 生态）

- **授权**：绝大多数不适合游戏使用（禁止商用或禁止改造），需逐个读日文条款
- **技术**：`.pmx` 需转换；MMD 骨架为舞蹈动画设计，含大量物理骨、缺少游戏引擎期望的标准骨架，改造成本高
- **结论**：不建议投入

### ysm 社区的 CC BY 模型（例如酒狐）

- **授权**：**CC BY，署名即可商用**——比 Rossi 干净得多
- **技术**：同为 Blockbench/YSM 格式，动画有同样的 Molang 问题
- **结论**：**如果对具体角色没有强偏好，优先选这一类**。授权不会永久限制项目走向

## 三个尚未解决的前提

在集成任何角色模型之前，这三件事必须先有答案：

1. **第一人称看不到身体。** 当前游戏是纯第一人称，角色模型无处可用。需要先有第三人称视角切换（对调试也有价值——从外部观察自己的跑酷动作比第一人称更容易判断动作对错），或回放/幽灵功能。
2. **授权决定项目上限。** 用了"仅非商"的素材，这个游戏就不能商用。这是不可逆的选择。
3. **画风是刻意选择而非中性选择。** Minecraft 体素角色 + 镜之边缘式干净建筑，是一个明确的风格决定，需要人来拍板。
