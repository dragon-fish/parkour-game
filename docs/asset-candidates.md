# 素材候选与授权记录

记录评估过的角色模型来源、授权状态，以及能不能真的用。**结论先行：目前没有任何一个可以直接集成，原因不是授权，而是格式与游戏视角。**

## 已评估

### Rossi（`C:\Users\xiaoy\Downloads\Rossi`）

- **格式**：Blockbench / YSM（Yes Steve Model），Minecraft 风格体素角色
- **构成**：`models/*.json`、`animations/*.animation.json`、`textures/texture.png`、`controller/controller.json`，共 3.3 MB
- **授权**：原作者允许**非商业**二次创作使用
- **可用性**：**几何、贴图、以及大部分动画均可用**

> **更正记录：** 最初的评估结论是"动画不可用"，那是错的。当时只看了名为 `run` 的动画（0 骨骼），并以整个文件 241 处 Molang 引用的总量下了判断，没有逐个动画检查。使用者实际导出 glTF 并播放，直接推翻了该结论。以下是逐动画核对后的真实分布。

`main.animation.json` 共 61 个动画，Molang 依赖程度差异极大：

| 动画 | 骨骼数 | Molang 引用 | 时长 | 判断 |
| --- | --- | --- | --- | --- |
| `奔跑`（真正的奔跑） | 21 | 4 | 0.667 | **可用**，标准关键帧 |
| `run` | 0 | 0 | 无 | 空占位符 |
| `jump` | 0 | 0 | 无 | 空占位符 |
| `walk` | 27 | **272** | 1 | **重度程序化，导出多半不对** |
| `idle` | 16 | 34 | 30 | 可能部分失真，需验证 |
| `sleep` / `ride` / `sit` | 45~56 | 0 | 有 | 纯关键帧，可用 |

对跑酷游戏而言这个分布算运气不错：**最关键的 `奔跑` 恰好是干净的关键帧**，落地翻滚等动作经实测也能正常播放。真正需要另行处理的是 `walk` 与 `idle`。

**另有一条思路可留作后手：** 那些重度 Molang 的动画本质上是"由移动速度驱动的程序化动画"，而 spec 里 P5 的方案正是程序化 IK，同样由移动状态驱动。`walk` 若导出不理想，可以用我们自己的 `horizontal_speed()` / `velocity.y` 去驱动对应骨骼，而不是去转换那 272 处表达式。

**方法教训：** 静态分析聚合指标（"全文件 241 处 Molang"）会掩盖分布。判断素材可用性应当逐条检查，或者干脆像使用者那样直接导出跑一遍——实测一次胜过推理十次。

### 模之屋（MMD 生态）

- **授权**：绝大多数不适合游戏使用（禁止商用或禁止改造），需逐个读日文条款
- **技术**：`.pmx` 需转换；MMD 骨架为舞蹈动画设计，含大量物理骨、缺少游戏引擎期望的标准骨架，改造成本高
- **结论**：不建议投入

### ysm 社区模型（例如酒狐）

> **更正：不要假设整个 ysm 社区都是 CC BY。** 最初的记录写成"这一类都是 CC BY，署名即可商用"，那是过度概括。实际拿来试的那只**大正女仆酒狐是 CC BY-NC-SA**——NC 禁止商用，而 SA 更麻烦：它会要求衍生作品沿用同一协议，等于把整个项目的授权锁死。**逐个模型确认，不要按社区归类。**

- **授权**：**逐个确认**。社区内既有 CC BY 也有 CC BY-NC-SA
- **技术**：Blockbench/YSM 格式。导出 glTF 时 Blockbench 会把程序化动画**烘焙成关键帧**，所以导出结果里 `idle` / `run` / `jump` 都有真实数据（分别 35 / 34 / 80 条通道），可直接用
- **实测发现**：导出的场景会连带整套用不到的内容——第二套异形骨架、GUI 网格、约 90 个多余动画片段。继承场景里把它们设为 `visible = false` 只是隐藏，并没有减少体积。真要瘦身要在**导入设置**层面处理
- **结论**：技术上可用，但**授权必须逐个核实**

## 已集成的机制

即便当前没有任何合规模型，挂载通路已经做好并测试过：

- `Player` 有 `body_scene: PackedScene` 导出字段，默认为空
- **不要在 `scenes/player/player.tscn` 上设它**——那是生成器产物，下次重新生成会被抹掉。要在**关卡里的 Player 实例上**设（实例覆盖存在关卡文件里，生成器碰不到）
- 运行时挂到 `BodyRoot` 下，自动接好 idle/run/jump 动画状态机与头骨跟随
- **没有模型时全部静默降级，不报错**——把模型从磁盘删掉，测试依然全绿

## 三个尚未解决的前提

在集成任何角色模型之前，这三件事必须先有答案：

1. **第一人称看不到身体。** 当前游戏是纯第一人称，角色模型无处可用。需要先有第三人称视角切换（对调试也有价值——从外部观察自己的跑酷动作比第一人称更容易判断动作对错），或回放/幽灵功能。
2. **授权决定项目上限。** 用了"仅非商"的素材，这个游戏就不能商用。这是不可逆的选择。
3. **画风是刻意选择而非中性选择。** Minecraft 体素角色 + 镜之边缘式干净建筑，是一个明确的风格决定，需要人来拍板。
