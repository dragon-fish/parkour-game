# 音乐转场：让一段音乐"变成"另一段，而不是"换成"另一段

← 返回 [README](../README.md)

主菜单的音乐要在玩家点击的那一刻从克制的循环进入副歌。第一版做出来是**突兀**的，
之后每一次修都不是靠调数值，而是靠先搞清楚**上一版为什么突兀**。这篇记录那条链条。

所有数值都是量出来的，量法附在最后。凡是"我们定的"和"从别处量到的"都分开标注。

---

## 1. 三种手法，只有一种适用于成品混音

| 手法 | 做法 | 适用条件 |
|---|---|---|
| **横向重排** horizontal re-sequencing | 在时间轴上跳到另一段 | 任何音频 |
| **纵向分层** vertical layering | 同一段编曲，开关某几轨 | **需要分轨** |
| **过渡片段 / stinger** | 在接缝上盖一段专门写的过门、riser 或一记镲 | 需要额外素材 |

很多游戏"大地图进战斗完全不突兀"，通常不是转场做得好，而是**根本没有转场**——战斗
只是把鼓和主奏那几层的推子推上去。同一条编曲，天衣无缝。

⚠️ **本项目的音乐是 AI 生成的成品混音，没有分轨，所以纵向分层用不了。**
这个前提决定了后面所有的选择。

### 分轨分离试过了，不行

用 Demucs（`htdemucs`）把母带分成 drums / bass / other / vocals：

- 四轨相加与原曲的残差 **−26.8 dB**（对齐后。未对齐时完全对不上，因为 stems 比
  mp3 晚 **1015 采样**，那是 mp3 编码器延迟）
- 副歌里 40–120 Hz 的能量：全开 0.150 → **去掉 drums 轨仍有 0.072**，只低 6.4 dB

📌 **电子乐的 kick 和 sub-bass 频谱高度重叠，模型分不开。** "去掉鼓轨"不等于"没有
鼓"；要真安静就得连 bass 一起去掉，剩下的又太空。分离结果没有留在仓库里，留下的是
这条结论。

## 2. 对齐是有层级的，只对齐到"拍"是最弱的一档

```
拍 (beat)  ⊂  小节 (bar)  ⊂  乐句 (phrase, 通常 4 或 8 小节)  ⊂  段落 (section)
```

**第一版的错误**：切入点选在副歌的第一小节，并保持拍相位对齐——节拍网格确实没断，
但那是**从副歌小节的中间**切进去的，于是**副歌自己那一记下拍（整段最重的一个瞬间）
被跳过了**。听感是"全奏突然出现"，没有"砸下来"。

📌 **不要切到目标段落本身，要切到作曲者写在它前面的那段铺垫。**

这就是中间件用过渡片段和 stinger 做的事的廉价版：**不自己造过渡，用作曲者已经写好
的那段当过渡。** 目标段落会自己走进来，带着它完整的下拍。

---

## 3. 相位保持：为什么切入点不是一个固定时刻

切入点是 `目标位置 + 当前相位`：

```
phase = fmod(循环已播时长, BAR)
entry = 铺垫小节的起点 + phase
```

因为**全曲 BPM 恒定**，这个相位在时间轴任何位置都成立。于是节拍网格在交叉溶解期间
完全不断，鼓点落在它本来就该落的地方。

⚠️ **前提是速度不变。** 曲子中途变速，这招立刻失效，只能退回"等下一个小节线"。

**代价是要保证提前量。** 相位保持意味着玩家在小节末尾按下时，留给铺垫的时间趋近于
零——实测在相位 1.79 s 时只剩 **19 毫秒**，目标段落会在滤波器还没打开、音量还没抬
起来的时候砸下来。所以要定一个下限，不够就整体退回一小节。

📌 **不要给"剩余时间"加下限钳制。** 那会让抬升越过下拍才结束，把问题藏起来而不是
解决。要动的是**入点**。

## 4. 包络：先让开，再进来

"包络"就是一个参数随时间怎么走的那条曲线。转场至少要有两条：

- **音量包络**：点击后**先下沉**，再推到目标音量
- **滤波包络**：从压着到放开

🔶 **从一款成品菜单实测**（点击约在 42.0 s）：

| 时间 | rms | 说明 |
|---|---|---|
| 42.00 | 0.109 | 点击 |
| 42.50 | **0.049** | 下沉到全窗最低，比点击前还低 **7 dB** |
| 42.75 | 0.049 | 维持 |
| 43.25 | 0.133 | 开始涌起 |
| **43.75** | **0.192** | 峰值 |

**点击后约 0.75 秒音乐反而变轻，1.75 秒后才到峰值**，而峰值落在角色起身的那一下。

📌 **两条包络必须在同一时刻收尾，落在同一个下拍上。** 否则听起来是三件事各干各的，
而不是一件事。

📌 **落点要对齐画面上的动作节点，不是对齐"流程结束"。** 本项目把它对齐到
`MainMenu.RISE_TIME`（起身），而不是菜单面板落位——后者晚一秒，音乐会显得拖。

## 5. 用滤波器模拟分层：闭合状态是"带"，不是"闷"

没有分轨也想要"乐器一层层进来"的听感，就得知道分层在频谱上长什么样。

🔶 **实测同一款菜单的安静循环 vs 完整编曲**：

| 频带 | 差值 |
|---|---|
| sub 20–80 Hz | **+7.3 dB** |
| low 80–250 Hz | **+8.0 dB** |
| **mid 250–2 kHz** | **+2.5 dB** |
| hi 4–10 kHz | **+7.4 dB** |

📌 **中频几乎不变，低频和高频各上来 7–8 dB。** 这就是纵向分层的频谱指纹：**旋律/和声
那层一直都在**，点击时加进来的是**底端（鼓和贝斯）和顶端（hihat、打击、空气感）**。

于是闭合状态应该是**中频带通**（高通 + 低通夹住中频），两端同时向外打开。

⚠️ **单独一个低通是这个指纹的反面**——它保留低频、砍掉中高频，听起来像"有人在拧滤波
器旋钮"，而不像乐器进来。本项目第一版就是这么错的。

### 扫频按倍频程走，不要按赫兹

音高是对数的。按赫兹线性推，几乎全部时间耗在最高那个八度里（那里基本没有内容），
真正有内容的几个八度一瞬间就跨过去了——听感反而是"啪"一下。

```gdscript
# 等长的时间跨过等量的八度
cutoff = from_hz * pow(to_hz / from_hz, k)
```

### 交叉溶解用等功率

两条线性淡入淡出在中点相加会**凹一个坑**。在连续的节拍上，那个坑就是音乐在点击那一
刻抖了一下。用 `cos(k·π/2)` / `sin(k·π/2)`。

## 6. 循环：无缝循环和"播完歇一下"是两种东西，构造方式不同

| 用法 | 构造 | 谁负责重复 |
|---|---|---|
| 连续无缝循环 | **头部与"原曲里紧接其尾部之后的素材"交叉溶解** | 引擎（采样级精确） |
| 播完整段、歇一下、再来 | 原样裁切 | 代码（`finished` → 等待 → 重播） |

📌 **无缝循环的正确构造是把头部和"真正的后续"混在一起**，这样接缝携带的是作曲者真的
写过的延续，而不是一刀切口。反过来，**有停顿的片段不该做这个处理**——那 25 ms 的混合
永远不会被当成延续听到，只会让开头糊掉。

**接缝质量要量，不要猜**：把循环点的样本跳变和曲子内部正常的相邻样本跳变相比。

```
menu_loop（8 小节）   跳变 0.28 倍于正常步长 → 听不见
副歌 16 小节            跳变 1.93 倍             → 每 29 秒一声轻响
```

⚠️ **切点长度要按"接缝好不好"来选，不能只按乐句。** 16 小节在乐理上更整齐，但它撞上了
曲子落下去做间奏的那一小节，接不上。

### 在音乐本来就安静的地方剪

🔶 实测那款菜单的循环跳接点：**跳接前 1 秒 rms 只有 0.055–0.060**，正好等于安静循环
的音量——编曲自己在那里落下去了，跳接就藏在这个天然的低谷里。

它跳回的位置也值得注意：**不是曲子开头，而是"点击后音乐刚进来的那一点"**（实测滞后
恒为 173.20 s，218.0 s 处的音频对应 44.8 s 处）。

## 7. 音量：菜单是玩家听到的第一个声音

- **从静音渐入**。窗口要一会儿才出现，第一帧更慢，一上来就满音量的话**玩家会先听到
  音乐再看到画面**。
- **交叉溶解要在低音量上完成**，抬升是另一段独立的慢动作。直接交叉到目标音量的话，
  那 0.6 秒本身就是一次跳变。
- **静音写 −80 dB，不要写 `linear_to_db(0)`**——后者是 `-inf`，混音总线拒收，结果是
  淡出的那一路整段维持满音量。

## 8. 怎么量

节拍网格是一切的基础，且**必须交叉验证**——单一方法会给出成倍或成 3:2 比例的错误答案。

1. **起音包络**：短时傅里叶 → 对数幅度 → 逐帧正差之和（spectral flux）
2. **速度**：对起音包络做自相关，取音乐合理区间内的峰
3. **相位**：以候选速度铺一把梳子，扫过一个小节内的所有偏移，取低频命中最强的
4. **精化**：检测底鼓起音，对 `t = 相位 + k·拍长` 做最小二乘拟合
5. **结构验证**（决定性）：正确的速度会让**段落边界落在整小节上**

> 本项目的曲子：三种方法给出 132.51 / 132.5076 / 132.63 BPM。前两者一致，第三者
> （波形自相关）是离群值。结构验证一锤定音：在 132.5076 下鼓正好在第 16 小节进、
> 副歌正好在第 32 小节，首个强拍在 0.000 s——其他速度都落不到整小节上。
>
> ⚠️ librosa 的 `beat_track` 在这首上给出 89.1 BPM（与真值成 2:3 关系）。**库不是权威，
> 结构才是。**

段落结构用**逐小节分频带能量**看：低频（20–150 Hz）看鼓和贝斯，中频（300 Hz–2 kHz）
看旋律，高频（4–10 kHz）看 hihat 和空气感。段落变化在这张表上一目了然。

`tools/cut_menu_music.py` 是最终落地的裁切脚本，会打印接缝质量数值。

## 一句话清单

- [ ] 速度至少两种方法交叉验证，并用"段落是否落在整小节"作最终裁决
- [ ] 切入**目标段落前面的铺垫**，不要切到目标段落本身
- [ ] 保持相位，并**保证最小提前量**（不够就退一小节，不要钳制剩余时间）
- [ ] 音量包络**先下沉再涌起**；所有包络在**同一个下拍**收尾
- [ ] 落点对齐**画面上的动作**，不是流程终点
- [ ] 闭合状态是**中频带通**，不是低通；扫频按**倍频程**
- [ ] 交叉溶解用**等功率**，且在**低音量**上完成
- [ ] 无缝循环才做头部溶解；有停顿的片段原样切
- [ ] 循环接缝的跳变要**量**，并**剪在音乐本来就安静的地方**
- [ ] 开场**从静音渐入**；静音是 −80 dB 不是 `-inf`
