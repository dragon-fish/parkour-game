# 教程关「虚空」设计

游戏的第一关，也是主菜单的替代品。玩家点击屏幕后直接获得操作权，在一片无尽平地
上学会全部必学动作，然后爬上一座螺旋塔，跳进塔顶的光球，落进第一关。

这一关同时承担三件事：教学、菜单、以及第一关的加载掩护。

## 叙事内核

**一个折翼的天使失去了天空的权能，但她没有放弃。她能做的就是奔跑、不要停下、向上。**

这不是套在玩法上的故事，是从玩法里长出来的——那三个动词字面上就是移动系统的说明书：

| 她要做的 | 承载它的机制 |
|---|---|
| 奔跑 | 速度曲线要跑很久才爬满（`speed_curve`） |
| 不要停下 | 损速无处不在且连续：转向、落地、每一次犹豫都在还债 |
| 向上 | 螺旋塔 |

**下面这些设计元素承载叙事，改动它们要付叙事的代价，不只是手感的代价：**

- **悬浮的神圣几何体**是天空的残骸，她失去的那个领域。不是美术风格选择。
- **地板塌陷**是「你不再拥有立足之地」。不许改成淡出——淡出只是转场，塌陷是剥夺。
- **零代价失败**是「没有放弃」的字面形态：她不会真的死，只是掉下来，再爬一次。玩家
  每按一次重置，都在扮演这个角色特质。这条同时是与 Only Up 一类游戏解绑的关键，
  所以它有两重理由，不是一个可以调的难度选项。
- **捷径**是她用双腿做到本该用翅膀做的事。玩家纵身跳过去、发现自己够到了的那一刻，
  就是她短暂重获飞行的那一刻——这个游戏最好的时刻，机制上与叙事上是同一个时刻。
- **医院和天堂是同一种白。** 手术无影灯的冷白与神圣光辉的白是同一种白的两种解读，
  所以「跳进光球 → 从医院醒来」做成同一片白、只是意义变了：她以为自己回到了天空，
  睁眼是无影灯。技术上就是一次白幕转场，本来就要做的那一次。

折翼如何发生、她自己知不知道，留到第一关，本文不定。

## 核心结构

**空间是环，时间是线。** 平地四边相接，玩家跑不出去也撞不到墙；教学内容按进度
推进，与位置无关。两条轴互不干扰。

| 阶段 | 空间 | 玩家在学 | 环面循环 |
|---|---|---|---|
| 一 · 苏醒 | 空的平地 | 我能动 | 生效 |
| 二 · 涌现 | 平地 + 单个障碍轮流出现 | 世界会回应我 | 生效 |
| 三 · 攀升 | 螺旋塔，平地已塌陷 | 动作可以接起来；路线可以自己选 | 已退场 |
| 落点 | 塔顶光球 | — | — |

## 环面

四边相接。玩家跨越边界时坐标平移一个周期，视觉与操作均无中断。

### 为什么这在本项目里是便宜的

- **相机不需要任何处理。** `camera_rig.gd` 的成员变量里没有一个存世界坐标——全
  是标量（`_pitch`、`_bob_phase`、`_dip`、`_roll`、`_speed_fov`）与局部偏移
  （`_head_local_offset`）。唯一读 global 的 `body_y` 是每帧现读。这是
  「相机只接收数值，不持有场景引用」那条架构原则的副产物。
- **浮点精度反而更好**，坐标永远在原点附近。
- **虚空没有远景参照物**，传送后没有天际线可以对不上。

### 传送的唯一门槛

**活动 move 的 config 声明 `holds_world_path = true` 时不传送。** 这不是
`ScriptedMove` 子类名单——判据是 `MoveConfig.holds_world_path`，声明在每个
move 自己的 config 上（`MoveManager.current_holds_world_path()` 读取）。持有
世界坐标目标点的都要声明它：Grab / SpeedVault / IntoGrab 这几个脚本动作，
LineMove 家族（Ladder / Zipline / Swing / Balance / LedgeWalk，均非
`ScriptedMove` 子类，但同样每帧从线的世界坐标采样重写位置），WallClimb（
用世界坐标锚点算漂移，传送会把锚点读成一次假漂移），以及 SpringBoard（两次
踏步内部组合了一个 `ScriptedMove`）。传送会把这些动作正在走的路径扯断。这些
动作都是短时长的，等它结束再搬，玩家察觉不到——虚空里他无从判断自己「本该」
在哪。

DO NOT 用「离边界多远」之类的距离条件替代这条判据，也不要用 move 的类名/继承
关系替代它——config 上的声明才是唯一可靠的信号。

### 不变量：传送不许改变任何相对关系

**玩家与一个物体的相对位置，只能因玩家真的走动而改变，绝不能因传送而改变。一个物体
消失的唯一理由是视觉距离太远。**

这条同时管住两端，也是判断任何新系统「接没接对」的唯一标准：

| | 规则 |
|---|---|
| 跨界时 | 世界里所有还该被看见的东西，与玩家做**同一个位移** |
| 回收时 | 判据是**到玩家的距离**，绝不是世界坐标 |

第二条容易被写错：跨界会让世界坐标不断累积偏移，拿它做回收判据会在错误的时刻销毁
东西——玩家眼前的盒子突然没了，或者早该消失的还赖着。

实现上有两种等价做法：**把物体搬过去**（一份实例，位置加同一个偏移），或者**预先在
每一格放一份 copy、跨界时换显示哪一份**。观感相同；前者省 8 份实例，后者的代价是
跨在接缝上的物体切换时会裂开，因而必须禁止物体生成在接缝带上。本项目用前者。

⚠️ **接缝是一面照妖镜**：任何忘了跟随跨界的系统，都会在玩家跨界的那一帧把自己暴露
出来——它持有的东西会整体跳一个周期。已知必须跟随的有：站住的障碍
（`TutorialDirector._on_wrapped`）、以及将来任何在世界里放东西的系统。

### 三个数

| | 含义 |
|---|---|
| `P` 环面周期 | 跑多远撞一次边界 |
| `R` 崩塌半径 | 几何体在多远外消失 |
| `S` 螺旋半径 | 塔的粗细 |

### 视距不受周期约束，因为场地里没有可重复的东西

**无缝传送的目的是让玩家能一直往前跑，不是让他看到无限份世界。**

#### 固定内容是个两难，跟平不平铺无关

把景物钉在场地里，只有两条路，而且都通向坏结果：

| 做法 | 代价 |
|---|---|
| 场地做大 | 玩家要跑很久才看得到东西，而且**在一片空地里容易迷路** |
| 视距做小 | 玩家跑到边界时**周围一个景物都没有**，而且「看不到头的地平线」当场没了 |

**「看不到头的地平线」是不可牺牲的**——它一旦没有，这一关的虚空就不成立了，剩下的
只是一个白色的房间。

跟随式内容是唯一同时满足三样的方案：地平线要多远有多远、玩家在任何位置周围都有东西、
场地不必大。

物品出现在玩家附近、跑远了被回收、再出现在他附近——本关的障碍本来就是这么摆的
（见「障碍是长出来的」）。于是远处没有任何一份「副本」，也就没有任何东西能在跨界时
暴露破绽，**视距想给多远给多远**，纯粹按空旷感来定。

⚠️ **DO NOT 把场地内容按周期平铺成 3x3 或更多份。** 这条弯路走过：试玩场地一度这么
做，为的是让作者「看见」传送发生。它能工作，但它把脚手架的性质变成了看起来像设计约束
的东西——

- 视距被迫留在平铺范围内（`R <= rings x P`）
- 周期被迫整除地面图案的间距，否则跨界时整片地面的点阵相位会跳
- 平铺份数得随视距反推，改一个忘一个就露馅

**这三条没有一条是环面循环的性质，全是平铺自己带来的。** 换成跟随式内容之后，它们
一起消失了，试玩场地的节点数也从 751 掉到 16。

唯一留下的是：**地面本身是固定的**，所以地面若带有可辨识的周期图案，那个图案的间距
仍须整除 `P`。均匀的地面没有这个问题。

地面基速 `pawn_config.ground_speed = 7.2 m/s`（冲刺更高）。按每约 10 秒穿越一次
边界，`P ≈ 100 m`，于是 `R < 50 m`。具体值在灰盒里用 F1 面板拨。

### 崩塌半径是三件事，不是一件

它同时是渲染距离、美学演出、和**传送掩护**。玩家在边界附近看不到下一个周期的内容，
所以没有东西可以用来比较，跳变无从被察觉。

DO NOT 为了画面更壮观而调大它——那会同时拆掉传送的掩护。

### 崩塌与传送同生同灭

两者都只属于前半段，都在玩家踏上螺旋时退场：传送退场是因为地板没了（见下），
崩塌退场是因为「看到自己爬过的路」直接要求不崩塌。

玩家不会把这理解成两套规则，会理解成**世界变实了**。

## 教学部分

### 一课 = 一整块场景，作为一个单位出现和消失

平地上一次只出现**一块**场景，教会一个动作，然后整块消失，下一块出现。不是铺开一片
障碍场，也不是散落一地的独立物件。

**一块场景是一个单位，不是一个物件。** 它包含要交互的那个障碍、它周围的地形、参照物
和红色引导——全部一起生长、一起崩塌。

**理由是注意力。** 教学需要焦点：这一课教的是「跳过这个缺口」，那么视野里就该有一处
正在长出来的东西，玩家的眼睛自然知道该看哪儿。二十几个各自淡入淡出的物件会把注意力
摊平，那时候玩家看到的是「环境在变化」，而不是「这里有件事要我做」。

每一块是一个 `.tscn`。分开成多个文件的理由是**编辑**：一堆重合的几何体在同一个场景
里没法调试。

📌 试玩场地（`scenes/debug_levels/void_plain.tscn`）故意是散落的，那是**另一个目的**
——它要「往哪看都有参照物」，好让作者判断传送和距离。不要把两者统一。

**编辑时分开，运行时全部常驻。** 障碍场景小到不需要动态加载，全部预实例化，按
顺序切 `visible`。没有加载抖动，没有时序问题。

### 障碍是长出来的，玩家看着它建成

障碍**永远在玩家前方**，并且**在他眼前生长出来**：先勾勒线框，外表面沿一条切面长
出，断层处以亮光遮住，羽毛随之飘散。参考刺客信条 Animus 的物质化。

**摆放距离因此是「看得清」而不是「看不见」。** 早期方案是把障碍藏在崩塌半径之外让
玩家跑进去，那样摆放过程无需解释——但它同时把这一关最好看的东西藏掉了。生长演出把
一件需要隐藏的技术债变成了要展示的主要景观：玩家看到的不是一个已经存在的东西从雾里
出来，而是**世界正在为他建造**。

几十米外看不清 3D 打印的细节，所以距离取决于两件事：看得清，以及下面这条不等式。

#### 生长必须在玩家到达之前完成

    生长时长 x 冲刺速度 < 摆放距离 - 余量

否则玩家会跑进一个只长了一半的障碍。这条同时决定了**碰撞何时启用**：生长完成时
一次性打开。让碰撞面跟着生长面推进是另一个量级的复杂度，不值得——保住上面这条
不等式就不需要它。

#### 摆放、跟随、锁定

环面上玩家可以朝任何方向跑，所以摆放要跟着他转：

| | |
|---|---|
| **摆放** | 锚点 = 玩家位置 + 朝向 × `SPAWN_DISTANCE` |
| **跟随** | 生长尚未开始、且玩家朝向已偏离锚点方向超过阈值时，挪到新的前方 |
| **锁定** | 生长一旦开始，锚点**永久钉死**，此后绝不再动 |

**锁定这一条是硬要求。** 少了它，玩家一转头就会看见障碍在虚空里飘，整关建立起来的
「世界是实在的」当场垮掉。

原地转圈会让障碍一直跟着转、永远开始不了生长——那只说明玩家没在往前跑，迈步就遇上了。

障碍诞生在几十米之外，所以**「几何体生成在玩家身上把人卡进墙里」这个隐患不存在**。

#### 崩塌是生长的反面，用同一套语言

障碍完成使命后**碎裂成一片光点，飘散消失**。

生长与崩塌共用一个消融 shader（噪声阈值向一个方向推进是长出，向回推进是散去），
共用消融边缘的发光，共用从网格表面发射的粒子。**光点是这个世界的物质基本形态，
实体只是它临时的样子**——玩家不需要任何解释就读得懂：聚起来是路，散开就没了。

DO NOT 给崩塌另写一套特效。三处演出（生长 / 崩塌 / 地板塌陷）必须是同一种物质语言，
否则它们各自为政，看起来像三个不同的系统在同一个场景里打架。

#### 演出可以先简陋，时序不能

**MVP 不需要那个 shader。** 生长可以先做成纯 alpha 淡入，甚至直接闪现；崩塌可以先
做成淡出。线框、切面推进、断层亮光、羽毛，全部是后补的。

**但时序契约从第一版就要成立**：生长要占满它该占的那段时间，碰撞要在那段时间结束时
才启用，`生长时长 x 冲刺速度 < 摆放距离 - 余量` 从头就要满足。

这条分界线的意义是：**「多久」属于机制，「长什么样」属于表现**。时序从一开始就对，
将来把 alpha 换成 shader 时不必改任何逻辑，也不会在换完之后才发现玩家能跑进半成品
里。反过来，先做视觉再补时序，等于把最难调的部分留到最后，而且那时候它已经被一堆
美术资产压着了。

同理适用于地板塌陷：MVP 可以就是整块淡出，只要"下方留下一片发光平面当高度计"这个
功能在。

#### 羽毛不是装饰

生长时飘散的羽毛**是她的羽毛**。一个失去飞行能力的人，脚下的路由羽毛长出来——世界
用她失去的东西给她铺路。

这跟「捷径是她用双腿做到本该用翅膀做的事」是同一条线。写在这里而不是当美术备注，是
因为它决定了羽毛不能被换成任何别的漂亮粒子：换掉就只剩泛泛的宗教感，那条线断了。

#### 新旧两波不许重叠

上一个障碍在新的摆下时开始消失，两者会短暂共存。摆放必须与**任何仍然存在的障碍**
保持最小间距，不满足就沿朝向继续推远——反正推远发生在 `R` 之外，玩家看不见。

正常情况下这条不会触发（刚通过的障碍在身后，新的在前方）。**它是为「玩家刚过完一个
障碍就掉头」准备的**：那一刻"前方"正是旧障碍所在的方向。

#### 环面传送时，已锁定的障碍跟着一起搬

玩家跨越边界时坐标平移一个周期。已锁定的障碍必须做同一次平移，否则刚才还在正前方的
东西会突然出现在身后一个周期之外。未锁定的不必管——它下一帧本来就要重摆。

### 教学序列

#### 骨架是一条心态曲线，不是一张动作清单

原版教程关的真正结构不是「教了哪 17 个动作」，而是**教玩家怎么想**。动作只是承载
那条曲线的载体。

| # | 玩家在学的心态 | 本关的载体 |
|---|---|---|
| 1 | 没有风险 | 空平地。只有跑，掉不下去，跑不到头 |
| 2 | 按一下就行，不用管时机 | 齐腰墙（跳过去，身体自己翻越）；低矮天花板（按住 Shift 就过） |
| 3 | 要注意时机 | 长坡加低矮开口（跑起来按 Shift 才是滑铲）；宽到跳不过的缺口（对准墙跳，墙跑过去） |
| 4 | 要有耐心 | 平衡木。速度被砍到 34%，冲是过不去的 |
| 5 | 加快节奏，组合按键 | 串联：跳 → 抓边 → 爬上 → 立刻再跳 |
| 6 | 不要恐高，掉下去没关系 | 平地边缘外悬空的红单杠。第一次掉落，见本文「第一次掉落是设计出来的」 |
| 7 | 路线是你自己选的 | 一处明显的分岔：主路是几个平淡的跳跃，旁边一根红单杠可以跳掉一整段 |
| 8 | 跳跃很爽，能伤你的东西不多 | 螺旋塔 |

第 1 段没有任何障碍，它的作用只有一个：让玩家发现往哪跑都跑不到头。

第 7 段必须在上塔之前完成。塔上散布着捷径，而玩家得先知道"可以不走主路"这回事，
否则他会规规矩矩爬完整座塔，然后错过这一关最想给他的东西。

#### 判据：段不可删，载体可换

改动作时先问它顶的是哪一段，再问换掉它曲线会不会断。

平衡木教的不是平衡木，是**要有耐心**；任何一个逼玩家慢下来的东西都能顶这一段。反过来，
删掉第 4 段而不补替代物，第 5 段的「加快节奏」就没有了对比，读起来只是又一组障碍。

#### 与原版的两处差异

**砍掉「奔跑时要小心危险」。** 原版用铁丝网教这一段（会伤人）。本关的契约是**她永远
不会死**，虚空里没有危险，这一段无处安放，硬塞会与三条死亡拦截自相矛盾。它属于第一关
——医院之后才是真实世界，而那正好是玩家从"她不会死的梦"里醒来的意义。

**加上「路线是你自己选的」。** 原版没教这个，它指望玩家自己悟。本关把它做成了捷径
系统，所以它在曲线上占一段。

#### 对照基准：原版教程关的实际顺序

作者实机记录，按出现次序：

    WASD -> 跳过前方的间隙 -> 滑铲从通风管道下面通过 -> 翻越比人略高的铁丝网
    -> 墙跑通过更宽的间隙 -> 低矮的小障碍（复习）-> 独木桥
    -> 爬上比人略高的屋顶（复习）-> 单杠摇摆跳 -> 爬水管 -> 屋檐横爬
    -> 踢墙 Q 跳 -> 檐走 -> 滑索 -> SoftLanding 软垫 -> 铁丝网（收腿跳）
    -> 踏板跳 -> 结束（之后是战斗教学）

三条可以直接拿来用的读法：

- **动词在前，名词在后。** 前五项全是玩家要按出来的动作；第九项之后几乎全是世界给
  的东西。
- **穿插复习，不是一路新东西。** 第 6、8 项明确是回头再考一次。本关同时用两种手法：
  复习（回头考）和串联（第 5 段）。
- **`Coil` 和 `Turn180` 压在倒数几位**，印证了它们是高级内容——本关把它们排除出必学
  列表，两边判断一致。

原版教了 17 项，因为它的教程关同时就是第一关：有屋顶、有城市、有真实路线，教学点摊在
一段完整关卡里。**本关是纯教学，没有关卡内容包裹，同样的密度会显得机械得多**，所以
名词只保留顶住某一段曲线的那几个，其余交给捷径。哪些名词非教不可取决于第一关会用到
什么，而第一关尚不存在——见「待作者拍板」。

#### 必学动词受「三句提示」约束

开局只教了「上」和「下」两个方向，所以必学动作必须全部落在这两个方向的自然延伸上。
`Coil` 和 `Turn180` 没有这样的延伸（前者是空中的第三种意图，后者在 `Q` 上），无提示
下几乎不可能被发现——它们不进必学列表。

## 螺旋塔

### 一整个场景

规模受「长度与第一印象」约束：圈数宁少勿多。

塔的全部路径预先在一个 `.tscn` 里摆好。道路随玩家上升逐段揭示，**已经过的部分
永不消失**——玩家必须能低头看见自己爬了多高，那是这一段的核心体验。

因此塔不分段加载、不分段卸载。它全是简单几何体，视锥剔除是引擎白送的；真需要
优化时 `MultiMesh` 是出路。

### 逐段揭示必须共用材质

材质的 GPU 管线在它**第一次真正被绘制**时才编译（见
`docs/seamless-loading.md`：常驻不等于预热）。一段路突然 `visible = true` 而它带
着一个还没画过的材质，那一帧会编译管线——正好卡在玩家要起跳的时候。

**塔上所有路段共用同一个材质。** 第一段画出来时管线就编译完了，之后每次揭示都是
免费的。给某一段加特殊材质会让那一圈掉一帧，症状是「只有第七圈会卡一下」。

### 地板塌陷

玩家开始攀爬时，平地撤走。**碎成光点、向下飘散、在下方重新聚成一片发光平面**——
与障碍崩塌是同一套物质语言，只是规模是整个世界。

那片光海因此有了来历：它不是凭空存在的背景，**它就是你刚才站过的地板**。

它留在视野里，越来越远，于是**它自己就是高度计**。地板若是干脆消失，会同时造成两个
问题——纯白虚空令人不适，以及玩家读不出自己爬了多高。这两个问题是同一个问题，而这一
个演出同时解决它们。

「你不再拥有立足之地」这层意思不减反增：脚下的世界不是被抽走，是**解体了**。

地板撤走之后掉下去 = 重置。所以螺旋阶段不存在「跑到环面边界」这件事。

## 捷径

高级动作不是教程的一段，而是**可选捷径**：涂成显眼的红色，摆在主路旁边，可以完全
无视，敢试就跳过一大段路。

它教的东西比动作本身重要：**这个游戏的路线不是给定的**。这是原版最核心、也最难用
文字教的一课。

### 分界线是「会跳够不够用」

**没有任何动作是全自动的。** 玩法主旨是游戏不替玩家做选择：主动的部分永远是**跳**，
手脚够到了什么之后怎么处理，是身体的事。

DO NOT 把这写成「接触即触发」——那是错的读法，而且很容易读出来，因为
`walking_move.gd` 里确实有一段地面翻越代码。它**永远不执行**：
`walking_config.gd:26` 把 `check_for_vault_over` 设为 `false`，还有一条 DO NOT
注释守着它（`06 §6.2 bCheckForVaultOver`）。`check_for_vault_over` 与
`check_for_grab` 为 `true` 的配置全部是空中状态（`Jump` / `Falling` /
`IntoGrab` / `WallClimb` / `SpringBoard` / `Coil`），墙跑本来就住在
`AirborneMove` 里。

于是捷径的分界线是：

| 能当捷径（跳就够了，零新知识） | 必须教（跳以外还要别的） |
|---|---|
| 翻越 `SpeedVault`、抓边爬上 `Grab`、墙跑 `WallRun`、单杠 `Swing`、滑索 `Zipline`、爬梯 `Ladder`、平衡木 `Balance`、檐走 `LedgeWalk` | 滑铲 `Slide`（蹲键）、空中收腿 `Coil`（蹲键）、180 转身 `Turn180`（Q）、蹬墙跳（要知道墙跑途中还能再跳） |

左列玩家看到红色的东西、主动跳过去，身体接管——**他学会的是「敢就行」**，而"敢"正是
这一关要教的。右列没教过就用不出来，跳过去什么也不会发生，学到的教训正好相反。

#### 唯一的自动例外，是一次救援

六种翻越变体里只有 `autostepuprightleg` 会在玩家没按任何东西时接管：跳一道宽缺口
没跳够，小腿撞到对面边缘，游戏在最后 0.2 秒蹬一脚把人送上去
（`airborne_move.gd:470-510`，三道门控，其中一条是「即将造成伤害的坠落不救」）。

`[ME:CONFIRMED 05 §5.7]` 六种变体里只有它要求**正在下落**（`MaxSpeedZ = 0`），
`MinHeight = 0` 说明它捞的不是障碍而是"你差一点没够着的那个面"，`LedgeOffset.Z`
是六种里最大的 0.9 m——不把你放在边沿，送进台面深处。没有手部 IK，动画名写着
`rightleg`：是腿的动作。

**它不违反主旨。** 它不替玩家做选择，它是在玩家做完选择、而且选错之后收学费——**用
损速买回一次死亡**。那是难度设计，不是操作设计。教程关不需要教它，玩家不需要知道
它存在。

### 捷径就是 Airborne 的出边

`AirborneMove` 出度 12（`Balance`、`IntoGrab`、`Ladder`、`Landing`、`LedgeWalk`、
`SkillRoll`、`SpeedVault`、`Swing`、`WallClimb`、`WallRun`、`Zipline`、`Walking`），
是整张转换图的枢纽。捷径系统不需要任何新机制——它是把这 12 条出边一条一条摆到玩家
跳跃的落点旁边。

### 主路的难度靠组合，不靠尺度

主路只用必学动作就能通过。难度递增的方式是**动作串联**（跳 → 抓边 → 爬上 → 立刻
再跳），不是把缝隙从 2 m 拉到 4 m。后者只教「跳得更准」，前者教「动作可以接起来」，
而衔接才是这个游戏的深度。

塔上每一圈组合一次前面学过的东西，捷径散布其间。

## 第一次掉落是设计出来的

教程要主动让玩家掉一次，越早越好。这个教学不可能失败：**跳过去了，他学到「大胆有
奖励」；没跳过去，他学到「失败无代价」——两个都是要教的。**

### 怎么安排

平地上没有可以掉下去的地方，所以第一次掉落靠**平地边缘之外悬空的一根红色单杠**。
玩家跳过去、够不着、掉进虚空、立刻回到平地。

一次同时教三件事：虚空是存在的（平地不是世界的全部）、掉进去只是重来、红色的东西
值得试。它还为后面的地板塌陷做了铺垫——玩家已经知道下面是什么了。

### 这一关里角色永远不会死

不是「把黑幕换成白幕」，是**死亡这件事根本不发生**。玩家不该看到掉血警告，不该看到
ragdoll 翻滚，不该看到死亡动画。她只是掉下去，然后回到刚才的高度。

一整套死亡演出在说「你死了，这很严重」，而这一关要说的恰恰是「没事，再来」——演出的
语气会直接抵消设计意图。

拦截要放在**每条通往死亡的路径的起点**，三条都要：

| 拦截点 | 项目现有行为 | 教程关 |
|---|---|---|
| `Health.hp` 跌破 30 | 继续掉血，屏幕边缘闪红 | 白幕重置 |
| 进入 `FallUncontrolled` | ragdoll 接管，播死亡动画 | 白幕重置 |
| `depth < -fall_recovery_depth` | `arena.gd` 明写 "A DEATH, not a rescue"，黑幕 | 白幕重置 |

**第二条是掉落的实际路径，漏掉它其余两条都没用。** `13-生命值与伤害.md` §13.2：
10 m 以上必死与血量无关——`FallingUncontrolledHeight = 1000`（10 m）是跨线即进入
失控状态，那 −100 只是给表演收尾。教程关掉进虚空的高度必然超过 10 m，所以血量那条
线根本不会被触碰，ragdoll 会先接管。只拦血量的话，玩家会看到自己翻滚着坠落，然后
才被救回来。

30 这个数不是新取的：`13-生命值与伤害.md` §13.4 记着本项目的表现阈值是「低于 50
转黑白，低于 30 屏幕边缘温和闪红」。在教程关一碰这条线就重置，意味着玩家永远看不到
那个警告。

### 这是关卡属性，不是玩家属性

同 `FogConfig` 的理由：一个 `MovementConfig` 要跨关卡携带，把「不会死」放进去会让
教程关和第一关无法各自为政。开关属于 `Arena`。

单一字段而非「开关 + 参数」两个，避免出现「不许死但阈值为 0」这类无意义组合：

```gdscript
## 血量跌破此值即白幕重置，同时把 FallUncontrolled 与落出世界一并改判为救援。
## 0 表示这一关允许死亡（默认）。
@export var rescue_below_hp: float = 0.0
```

### 玩家必须知道自己为什么掉

诱惑物要**看起来就远**——诱人，但明显有风险。玩家跳之前心里有数「这个有点悬」，
掉下去就是学习；他觉得「明明看起来能过」，掉下去就是游戏在耍他。

DO NOT 做一个看起来稳过、实际过不去的跳跃。那不是教学，是欺骗，而且它教会玩家的是
不要相信自己的判断——与整关的意图完全相反。

## 长度与第一印象

这一关是玩家看到的第一个画面，它定义整个游戏是什么。悬空几何体 + 垂直攀爬 + 掉下去
重来，在截图上与 Only Up 一类的攀爬游戏高度重合。**教程关过长，玩家会以为攀爬悬空
几何体就是核心玩法。**

### 解绑靠的不是「短」，是「快」

那类游戏的体验是站在小平台上小心对准、跳、怕掉下去。这个游戏的体验是全速冲刺、墙跑、
一气呵成。两者在截图上像，在手上完全不像。

因此螺旋塔的路径必须是**跑出来的，不是爬出来的**：一条需要保持速度才能连贯通过的
路，而不是一串需要精准落点的平台。这与「难度靠组合不靠尺度」是同一条要求——动作串联
本身就要求流动。

DO NOT 在塔上放需要停下来瞄准的跳跃。够不着就该是走捷径的信号，不是练习落点的信号。

### 两个天然的解绑点，要用足

1. **零代价失败。** 那类游戏的恐怖全在掉下去损失一切；这里第一次掉落后立刻回到
   原位。那一刻玩家就知道这不是同一类游戏——见「第一次掉落是设计出来的」。
2. **比例。** 平地是水平高速跑动，也就是这个游戏真正的样子；塔是期末考试。**平地
   阶段应当比塔长。** 塔要短而密集：每圈一个组合考点加一条可选捷径，圈数宁少勿多。

捷径在这里有第三重作用：敢冒险的玩家体验到的塔更短，于是他得到的第一印象更接近这个
游戏真正的节奏。

## 进度与失败

- **存档点按 `Checkpoint.index` 排序**：低位不能覆盖高位，同位最后触碰者胜。已实现。
- 掉下去 = 回到爬过的最高点，**代价只有时间，没有进度**。
- 掉到塔底之下走同一条重置路径，不需要单独的死亡判定。

零代价失败是「大胆尝试捷径」成为理性选择的前提：奖励是跳过一段路，代价只是重来一次,
所以试永远划算。它同时是与 Only Up 一类游戏解绑的关键，见「长度与第一印象」。

## 视觉与氛围

本关的美术方向尚未定稿。作者手边有两张 codex 生成的冷白 + 红引导概念图，画的是
第一关（医院）而不是这一关，未入库。

无论将来用哪张参考图，规矩不变：**生成的概念图是美术参考，不是关卡蓝图。** 图上的
尺寸标注不是从移动参数推出来的，照着搭会得到一个看着对、玩起来处处别扭的关卡——而且
症状会伪装成手感问题，害人回头去改那些已经量准的数。几何先由参数算出、灰盒跑通，
美术方向随后套上。

### 神圣不是恐怖

纯白 + 无方向光 + 无边界 = 感官剥夺。要的是崇高，差别可以拆开：

| 恐怖 | 神圣 |
|---|---|
| 光均匀弥漫，无方向 | 光从某处来，通常是上方 |
| 没有天地轴 | 天地分明 |
| 无限（迷失） | 有边界，但很远（崇高） |
| 空无，没有目标 | 有一个正在前往的东西 |

落地做法：

1. **塔顶光球从第一秒就可见。** 白色虚空可怕是因为没有目标；有一个发光的东西悬在
   上方，空间的意义就变了，而且它顺带解决了全程引导。
2. **上下渐变**：下方渐深（深蓝或冷灰，不必是黑），上方渐亮向光球。天地轴由此立起，
   高度也读得出来。
3. **不要纯白无影。** 原版从来不是纯白，是白建筑 + 蓝天 + 深阴影 + 红引导。项目里
   `Arena.COLD_AMBIENT_TINT` 就是一个蓝色 `(0.22, 0.47, 0.74)`。

`arena.gd` 里那条「雾允许遮蔽天空的程度为零」的常量说明记着同一个教训：一个连天空
也吃掉的雾会把视野变成 a flat white void，比它想藏起来的地平线更糟。

## 音乐

施工细则全在 `docs/music-transitions.md`，那是主菜单同一个转场的施工记录，本节不重复
它，只定这一关的四条。

### 一、循环段贯穿前半关

从她站起身到塔出现之前，全程是克制的循环段。**首次启动没有主菜单，所以「点击进副歌」
那个转场在这一关不发生**——她站起来时音乐保持循环。

第二次之后从主菜单进入教程关，若用同一首曲子，音乐可以完全不中断，正好对上
`docs/seamless-loading.md` 的一镜到底。

### 二、副歌整关只用一次，给塔

这是这一关唯一的音乐高点。DO NOT 在别处（第一次掉落、第一条捷径、某个障碍教完）也放
一次——用两次就没有一次是重的。

### 三、切入点在铺垫段，不在副歌本身

`music-transitions.md` §2 记着第一版的错误：切到副歌第一小节，节拍网格没断，但**副歌
自己那一记下拍被跳过了**，听感是全奏突然出现，而不是砸下来。

所以时序是反的：**切入发生在塔出现之前**，进的是作曲者写在副歌前面的那段铺垫；塔升起
那一下正好吃到副歌的下拍。落点对齐**画面上的动作**（塔升起），不是"教学流程结束"——
同 §4，主菜单对齐的是起身而不是菜单面板落位。

### 四、塔等音乐，不是音乐等塔

**塔的出现不是「教学走完」的直接后果**，中间隔着一次音乐对齐的等待：

    教学序列走完 -> 等到下一个乐句边界 -> 铺垫进来 -> 塔升起 + 副歌下拍

中间那段空白是呼吸，不是浪费。这与 §3 「提前量不够就整体退回一小节，动的是入点而不是
钳制剩余时间」是同一个思路。

`TutorialDirector` 因此不能在最后一个障碍完成的那一帧就掀开塔——它要把「可以开始了」
交给音乐，由音乐决定哪一帧。

## 开场与落点

- 点击屏幕 → 红色剪影站起身 → **不显示菜单** → 镜头落到剪影身后（第三人称）→
  玩家直接获得操作权。
- 红色剪影的视觉已存在：`main_menu.gd` 在 SubViewport 里用
  `silhouette_glitch.gdshader` 做三段式着色，无模型也能工作。
- **起身这一拍已经实现了，在主菜单里。** `main_menu.gd` 的 `_beat_rise_begin()`：
  第 0 帧就是蹲姿 + 白色标记 + 微弱地板，然后身体站起、相机 ease-in-out 拉出、logo
  淡出、地板点阵与镜面到位。**教程关开场与它只差终点**——主菜单拉到正面全身然后出
  菜单，教程关落到剪影身后交出控制权。前半段整段复用。
- 其中一条设计约束照搬：**身体只站起来，从不转身；所有转动由相机完成。**
- 起身当前是 `Crouch_Idle -> Idle` 的引擎混合，`BODY_STAND_BLEND = 1.5` s（= `RISE_TIME`，
  相机落位那一帧身体正好站直）。**不是 `Crouch_Exit`。**
- `Crouch_Exit` 是一个**升级项，不是缺失素材**：它有真实的重心转移，而混合只是两个
  静态姿势之间插值。但它只在付费的 UAL1 完整版里，免费的 `ual1_standard.glb` 只有
  `Crouch_Idle_Loop` / `Crouch_Fwd_Loop`。本项目的底线是没有付费包也跑得起来，所以
  写成优先级回退：**有 `Crouch_Exit` 就播它，没有就退回现在这个混合**——两条路都
  不会让人看到 T-pose 或僵在半空。这与 `character_animator.gd` 的惯例一致。
- 库里的 clip 名带 `_Loop` 后缀而主菜单查的是 `Crouch_Idle`，中间有一层改名或别名。
  接 `Crouch_Exit` 时走同一层，不要直接写库里的原名。
- 第三人称相机已完整（`V` 切换，`CameraRig` 视其为保存的偏好）。
- 落点：塔顶光球 → 白幕 → 第一关，从医院醒来。白幕符合项目的转场约定（正常转场
  白幕，死亡黑幕）。
- 「醒来」反过来给虚空一个叙事解释，玩家不会追问自己刚才在哪。

## 明确不做

- **不做环形跑道**（把平地做成一个物理闭合的环）。持续单向转弯会让玩家全程处在转向
  损速里，教给他的第一件肌肉记忆就是错的；而它并不省成本，一整圈几何比一个周期块更多。
- **不给平地加天空盒**。虚空的无参照物是传送不露馅的前提。
- **不在教程里教被动状态**（`FallUncontrolled` / `SoftLanding` / `Landing`）。玩家
  不需要知道它们存在。
- **不为捷径写新机制**。捷径是既有转换图的摆放问题。
- **不把塔做长**。见「长度与第一印象」。塔是这一关最容易失控的部分，因为每加一圈都
  很容易，而代价要到玩家形成第一印象之后才显现。

## 测试

粒度：**一个障碍 = 一个动作 = 一个测试**。每个障碍场景可以像一个函数一样被单测——
用 `ScriptedInputSource` 驱动，`tests/world_fixture.gd` 作夹具，断言给定输入下玩家
进入了预期的 move 并越过了障碍。

这让移动数值的改动能立刻定位到「哪一段过不去了」，而不必手动重跑。

结构性不变量（传送不打断脚本动作、低位存档点不覆盖高位、揭示不改变已揭示部分）写
断言；几何尺寸、崩塌半径、光球亮度这类会频繁调且改坏了一眼可见的值不写。
