# 爬梯子 / 竖直水管（Ladder）设计

复刻原版 `TdMove_Ladder` + `ladder_TdLadderVolume`。⚠️ CDO 附录里没有任何
Ladder 数值（已核对 A1 全量），所以本设计的所有数字都是**旋钮初值**，走滑索
的老路：先给可调参数，作者回 PC 实测后校准。

## 证据与裁定

- 05-动作库总览：梯子/水管属于「沿一条线交互」家族，靠兴趣体积标记。
- ✅ 作者裁定：**水管和梯子性质相同，有明确的「正面」**，只能面向它爬，
  没有环抓；「暂时没在 ME 里遇到可以调整攀爬面向的水管，梯子只有一面可以
  进入」。差异只在 IK 动画（存疑），机制上是同一个动作。
- ✅ 作者裁定：**横着的管道不是这个动作**——ME 里那就是可抓边的凸起，
  归现有的抓边系统，本设计只做竖直线。

## 场景标记

`InterestLine` 增加 `Kind.LADDER`。摆放约定：

- 曲线**竖直**画（底点到顶点），线就是梯子/管道的中轴。
- 节点自身的 **-Z 指向玩家站的那一侧**（与 Checkpoint 的朝向约定一致，
  编辑器里同样可用「将旋转与视图对齐」摆）。俯仰无意义，yaw 定义正面。
- 体积仍由 InterestLine 自动生成，半径沿用现有默认。

## LadderMove（状态承载型，非 ScriptedMove）

### 进入

- 空中、地面、**滑墙中**走进体积均可吸附（✅ 作者：ME 有一关就是滑墙
  接水管设计的，「检测可能是个正面180°扇形」——即正面半空间）。
- **正面门**：玩家中心须在梯子的正面半空间（在节点 -Z 一侧）。条件只有
  这一个——在正面就抓，不在就不抓；从背面穿过体积不吸附，踢墙跳越过
  背面的水管不会被黏住。
- 状态机准入：wallrun 系状态和空中/地面一样可被 LADDER 线截获，不得只
  开放给 Falling/Grounded。
- 磁吸淡入（`fade_in_time`，同滑索/单杠的形状）：位置拉到线上、身体转到
  面朝梯子（yaw = 梯子正面的反方向）。淡入结束居中视角扇（`_centre_fan`
  的既有形状）。
- 抓住瞬间垂直速度清零，水平速度丢弃；`fall_tracker.reset` 每 tick 重置
  （手抓着实体，坠落计费从松手起算——滑索/单杠定过的规则）。

### 攀爬

- W/S 沿线上下，恒速 `climb_speed`（初值 1.8 m/s）。
- **位移带碰撞检测**（✅ 作者）：每 tick 的攀爬位移经 `move_and_collide`
  （或等价的 test_move 预判）落地，而不是像滑索/单杠那样直接写
  `global_position`——那两个悬在空中，梯子贴着建筑。效果：向下爬到
  **脚触地**即自然松手转 Grounded（这就是"到底"的检测，比线端点可靠）；
  向上**撞到头**即停住，不会穿过天花板/舱口。线段端点仍作软钳制
  （顶端触发出梯判定、底端触发松手判定），碰撞是硬保底——线拉得比
  实际梯子长一截也不会出事——✅ 作者：设计师难免把线的末端插进墙体
  一点避免出 bug，碰撞保底让这种摆法安全。
- **顶端 + 仍按 W**：✅ 作者定形——先探测梯子顶端「后面」（+Z，墙内侧）
  `top_exit_reach`（初值 1.2 m）范围内有没有可站立的平面（复用现有的站立
  净空/落点探测机制），有则用**贝塞尔曲线把胶囊搬过去**（StepUp 同族的
  脚本位移：脚本动身体、视点按既有权重跟随，时长 `top_exit_time` 初值
  2.0 s——✅ 作者：「不止0.5s，可能得有2s」），动画先用 **ClimbUp_1m
  同款**，落定转常规着地。✅ 作者怀疑 ME 里这就是 ClimbUp 的逻辑——
  实现时优先尝试直接走现有的 ClimbUp/攀上脚本通道（入点换成梯顶），
  而不是另起炉灶；走不通再退回自建贝塞尔。探不到可站面则留在梯上，
  W 无事发生。这段搬运就是速通技巧里绕过的「漫长退出动画」。
- **底端 + 仍按 S**：松手，正常下落。
- 蹲：任意高度松手，纯脱离，`consume_roll()`（一次按键一次动作的既有规则）。

### 跳出：复用 GrabJump 的形状

✅ 作者：「在梯子里原地不动的时候很多操作几乎和 Grabbing 一样」，且
「AD+空格如果没有其他梯子是不会触发跳的」。所以**没有自创的方向跳**，
空格的优先级链是：

1. **方向键按着且该方向扫到目标线** → 快捷吸附（下节）。
2. **否则，扭头超过 `jump_angle_deg`（45，同 GrabAllowedJumpAngle 的语义）**
   → 朝完整 3D 视线方向跳出（GrabMove `_push_off`/`_launch_direction` 的
   同款形状：含俯仰、不投影掉入墙分量），速度旋钮 `jump_speed`（初值取
   grab 同名值）。左跳/右跳/后跳都是这一条——头看哪儿跳哪儿。
3. **否则（正对梯子按空格）**：无操作（W 才是爬）。

蹲 = 任意时刻松手 + `consume_roll()`，与 Grab 的写法逐行同构。

### 🔒 受保护的技巧：顶端斜跳接 VaultOver

✅ 作者：「在即将到达梯子顶端的时候斜方向跳出去可以用 VaultOver 收尾，
而不是漫长的退出梯子动画」——grab 那边同族 glitch 的梯子版
（见 grab_move.gd `_launch_direction` 的整段注释）。它由三个已定条件
自然涌现，实现与后续维护都**不得**破坏其中任何一个：

1. 视线跳保留入墙分量（不投影）。
2. 跳出后的空中状态照常运行 vault/抓边探测。
3. 顶端不自动播退出——翻上只由「顶端 + 持续按 W」触发，空格在任何
   高度（包括最顶端）都优先走跳出链。

需要一条测试钉住：接近顶端、视角斜 45°+ 跳出，vault 探测须能接住沿口。

### 快捷吸附（assisted hop）

方向+空格时**先扫描后跳**：

1. 在按下方向的半空间里（梯子系，±X 或 -Z），找 `snap_range`（初值 4.0 m）
   内最近的**其他** InterestLine（LADDER / SWING / ZIPLINE 通吃，冷却中的线
   跳过，自己这根跳过）。距离取玩家位置到目标线最近点。
2. 找到：解一条经过目标最近点的抛物线（给定 `snap_flight_time` 初值 0.55 s
   反解初速度，含重力项），把玩家按普通空中状态扔出去——**接住由目标线
   自己现成的 catch 逻辑完成**，本移动不做任何特殊落点处理。不需要镜头
   对准。
3. 没找到：**不跳**（✅ 作者），落回上节优先级链的第 2/3 条。

### 冷却

`note_line_left` 按线冷却 `same_line_redo_time`（初值 0.6 s，防止松手瞬间
被同一根重新吸回）。

### 顺带：滑索的同款碰撞保底

✅ 作者：ME 里滑索撞到东西也会强制退出——「鲜有滑索中途放障碍的设计，
一般都是滑到底忘记放手撞到墙被弹出去了」。所以 ZiplineMove 的每 tick
位移同样换成碰撞检测式：碰撞发生即强制松手转 FALLING，带着碰撞后的
残余速度被"弹出去"，不再无声地把胶囊怼进墙里。单杠不需要（悬空摆动，
摆进墙属于关卡摆放问题）。补一条测试：骑滑索撞墙必须脱线。

## 共享基类抽取（第三个客户到了）

Zipline / Swing 各自重复的公共件抽到 `LineMove extends Move`：

- 线获取与中止守卫（`nearest_interest_line` + `_aborted`）
- 淡入磁吸（`_fade` 计时、位置 lerp、`_turn_body_to` 跨淡入转身）
- `_centre_fan`（一次性居中视角扇）
- exit 时按线冷却
- **碰撞检测式位移 + 碰撞强制脱线**（滑索、梯子用；单杠不用）

三个子类只写各自的物理与出口。**抽取以两旧套件测试全绿为准**，不改任何
现有行为与数值。

## 配置

`LadderConfig`（MoveConfig 子类，进 MovementConfig 注册表 + F1 面板）：
`climb_speed`、`fade_in_time`、`jump_angle_deg`（45）、`jump_speed`、
`top_exit_reach`、`top_exit_time`、`snap_range`、`snap_flight_time`、
`same_line_redo_time`、`fall_limit`（沿用家族惯例 6.0）。

## 动画

沿用家族做法：SWING/ZIPLINE 式的手臂位——MVP 用现有 gate 通道挂一个攀爬位
（无专用动画就先用 Grab 系的静态位），IK 手贴梯细化排入 feel-backlog。

## 实现落地（as-built）

以下四点是实现阶段相对原计划的偏离，均经控制者确认接受：

- `check_for_ladder` 挂在 `move_config.gd`（`MoveConfig` 基类）上，不是计划
  设想的某个 `airborne_config.gd`——仓库里根本没有这样一个中间类，
  `FallingConfig`/`JumpConfig` 都直接 `extends MoveConfig`，旗标只能落在
  两者共同的基类上（默认 `false`，两个子类各自打开）。
- `LadderConfig` 比上面「配置」一节列出的旋钮多两个：`stand_off`（0.4，
  攀爬时胶囊中心离线正面的站位距离——不设的话胶囊中心就贴在梯子所在的
  墙面上，会穿模）与 `snap_cone_dot`（0.7，快捷吸附一节里内联的 45°
  瞄准锥门槛，提成了旋钮而不是写死的常数）。二者都是实现必需，不是
  设计遗漏。
- 顶端出梯的移交状态是 `WALKING`，不是字面意义上的 "GROUNDED"——`Move`
  的常量表里从来没有 `GROUNDED` 这个名字。落地点未经胶囊路径的碰撞验证
  （只是一次探测得到的落点），所以移交后不直接声明 grounded，而是让
  `WalkingMove` 自己下一 tick 的地面吸附来做真正的验证，与 GrabMove 的
  mantle 收尾同一套道理。
- 磁吸淡入（`fade_in_time` 区间内）仍是直接写 `global_position`，只有淡入
  结束后的常规攀爬才经 `slide_to()` 做碰撞检测——沿用 Task 3 给整个
  "沿一条线" 家族定的规则：磁吸本身的拉力不该被中途蹭到的几何体打断，
  碰撞保底只兜住已经吸附上、稳定攀爬的阶段。
